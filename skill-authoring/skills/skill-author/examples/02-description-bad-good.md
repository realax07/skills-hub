# Пример 2: description, который не срабатывает

## Запрос

> я сделал скилл для отчётов по выгрузкам, но агент его почти никогда не берёт, сам пишет pandas с нуля. глянь что не так

Скилл `sales-report/`, во frontmatter:

```yaml
description: Скилл для генерации отчётов.
```

А в теле — длинный раздел «Когда использовать: выгрузки из CRM и 1С, CSV и Excel, итоги за период, топ менеджеров…».

## Ход работы

1. `python3 scripts/validate_skill.py sales-report` → `! description короткий`, `! в description не видно, когда применять скилл`.
2. Диагноз: агент видит до срабатывания только description. «Скилл для генерации отчётов» не содержит ни одной сущности
   из реальных запросов («выгрузка», «csv», «итоги за квартал»), а раздел «Когда использовать» в теле грузится уже после решения — он не помогает.
3. Собрать 5 запросов «должен» и 3 «не должен» (из истории пользователя и по смыслу):
   - должен: «вот выгрузка из црм, сколько продали в сентябре», «посчитай итоги по этому xlsx», «сделай сводку по менеджерам», «отчёт за 3 квартал из 1с», «что по динамике продаж, файл в data/»;
   - не должен: «построй дашборд в Grafana», «почини импорт CSV в нашем сервисе», «напиши SQL-запрос к базе».
4. Перенести «когда» из тела в description, добавить сущности и границу. Раздел в теле удалить целиком: тело — только про то, как строить отчёт.
5. Добавить тест-кейс на косвенный запрос без слова «отчёт» (`new_eval.py … --prompt "сколько продали в сентябре? файл data/sales.xlsx"`).

## Плохо

```yaml
description: Скилл для генерации отчётов.
```

Почему плохо: нет «когда», нет сущностей (CSV, Excel, CRM, итоги), нет результата. Запрос «сколько продали в сентябре»
не пересекается с ним ни одним словом — агент решает сделать сам.

## Хорошо

```yaml
description: Строит отчёты по выгрузкам продаж из CSV и Excel (CRM, 1С, маркетплейсы) — чистит данные, считает итоги, динамику и рейтинг менеджеров, выдаёт Markdown-отчёт с таблицами и PNG-графиками. Используй, когда пользователь даёт выгрузку или таблицу и спрашивает про продажи, выручку, итоги за период, «сколько продали», «кто лучший менеджер», просит сводку или отчёт — даже если не говорит слово «отчёт». Не для дашбордов в BI-системах и не для импорта данных в приложения.
```

Почему хорошо: результат и сущности (CSV, Excel, CRM, 1С) + формулировки пользователя («сколько продали», «кто лучший») +
«даже если» для косвенных запросов + граница с соседними задачами (BI, импорт), чтобы не срабатывать лишнего.
Все 5 запросов «должен» пересекаются с ним, 3 «не должен» исключены.
