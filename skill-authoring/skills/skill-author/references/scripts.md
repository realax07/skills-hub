# Скрипты и зависимости

## Когда нужен скрипт

| Да, скрипт | Нет, инструкция |
|---|---|
| Шаг детерминирован: парсинг, конвертация, подсчёт, проверка формата | Нужны суждение, вкус, понимание контекста |
| Агент на каждом запуске писал бы одинаковый код | Код каждый раз разный и короткий |
| Ошибка в шаге дорогая и её легко допустить руками (даты, кодировки, экранирование) | Шаг — одна стандартная команда (`git log`, `ls`) |
| Нужна валидация результата перед сдачей | Проверка — «посмотри, что получилось» |

Признак на тестах: в трёх прогонах агент написал три похожих вспомогательных скрипта → это кандидат в `scripts/`.

## Конвенции CLI

Стартовые шаблоны: Python — его кладёт `scripts/init_skill.py` (`--lang py`), Node — `assets/extras/main.mjs.tmpl` (`--lang node`).

- **Только стандартная библиотека**: Python 3.9+ или Node.js 18+. Остальное — через установщик (ниже).
- **Кроссплатформенно**: пути через `pathlib` / `node:path`, без bash-специфики, кодировка UTF-8 явно.
- **`--help`** с описанием и примером вызова (первая строка docstring — она в `--help`).
- **Коды выхода**: 0 — успех, 1 — ошибка во входных данных/результате, 2 — неверные аргументы. Агент ориентируется на код, не на текст.
- **`--json`** для машинного вывода: агенту проще разобрать JSON, чем таблицу.
- **Сообщения об ошибках — что не так и что делать**: `error: файл не найден: x.csv` лучше трейсбэка.
- **Идемпотентность**: повторный запуск не портит результат; перезапись — только явным флагом.
- **Не трогать то, что не просили**: скрипт пишет в указанную папку, а не рядом с собой.
- Длинные скрипты разбивай на `scripts/lib/`; в SKILL.md упоминай только точки входа.

В SKILL.md для каждого скрипта: как вызвать, что вернёт, что делать при ошибке.
`python3 scripts/collect.py <репо> --since v1.2 --json` → `{"feat": [...], "fix": [...]}`; код 1 — не git-репо.

## Зависимости

Скиллы раскатываются на чужие машины, поэтому всё вне стандартной библиотеки объявляется и ставится явно:

1. **`compatibility`** во frontmatter: рантайм, пакеты, сколько весит, куда ставится.
   `compatibility: Python 3.9+. pypdf и Pillow ставит scripts/setup.py (≈15 МБ, в ~/.cache/agent-skills/pdf-tools).`
2. **Установщик** — `scripts/setup.py` или `scripts/setup.mjs` (`init_skill.py --setup py|node`, шаблоны в `assets/extras/`):
   - **проверяет реальным вызовом, а не по путям**: зависимость ищется так, как найдёт рантайм агента (проект, глобально,
     NODE_PATH, текущий Python, кэш скилла), и вызывается — импорт, `--version`, запуск браузера. Работает — ставить нечего;
   - без аргументов — сначала проверка, ставит только при неудаче; `--force` — ставит принудительно;
   - `--check` — только проверяет, код 0/1, пишет, чего не хватает и где нашлось;
   - ставит **вне папки скилла**: `~/.cache/agent-skills/<скилл>/` (Windows: `%LOCALAPPDATA%\agent-skills\<скилл>\`),
     с переопределением через `<СКИЛЛ>_HOME`. Скилл бывает симлинком в git-репо или read-only копией;
   - версии пиннует — одинаковое поведение везде.
3. **Первый шаг процесса** в SKILL.md — `setup` (он сам проверит и поставит только недостающее).
4. **Системное** (Node.js, Python, пакеты через sudo, браузерные библиотеки) не ставь молча: проверь и скажи пользователю, что нужно.

Как скрипты находят зависимости:
- Python: запускай скрипты тем интерпретатором, который печатает `setup.py --check` (текущий, если модули есть у него, иначе venv скилла).
- Node: `loadDep("<пакет>")` из шаблона `setup.mjs` — ищет в проекте, NODE_PATH, глобально и в кэше скилла.
  Не `createRequire(<конкретный путь>)`: у пользователя пакет может стоять в другом месте.

## Безопасность

- Никакой отправки данных наружу, которая не следует из описания скилла.
- Секреты — из окружения или от пользователя, не в файлах скилла.
- Скачивание бинарников — только с официальных источников и пиннованных версий, и это должно быть в `compatibility`.
