# description: как писать, чтобы скилл срабатывал

description — единственная часть скилла, которую агент видит до решения «брать или нет».
Плохой description = скилла нет, сколько бы хорошего ни было внутри.

## Формула

```
<Что делает: глагол + объект + результат, 1–2 предложения, с ключевыми сущностями>.
Используй, когда <типичные запросы и ситуации через запятую> — даже если <косвенные формулировки / пользователь не называет X>.
[Не применяй для <соседняя задача> — для неё <что вместо>.]
```

## Правила

1. **Что + когда.** Описание без «когда» агент не свяжет с запросом пользователя.
2. **Слова пользователя, а не автора.** Пользователь пишет «сделай заметки к релизу», а не «запусти генератор changelog по conventional commits».
   Перечисли синонимы и бытовые формулировки: «changelog, release notes, что поменялось, заметки к релизу».
3. **Чуть настойчиво.** Агенты склонны не брать скиллы и делать сами. «Используй, когда…, даже если пользователь не говорит слово X» заметно поднимает срабатывание.
4. **Конкретные сущности.** Форматы файлов, инструменты, типы артефактов: «.xlsx, .csv», «Playwright», «мокапы, UI-кит».
   По ним агент сопоставляет запрос со скиллом.
5. **Границы, если есть соседи.** Когда рядом похожий скилл — одна фраза «не для X», чтобы они не конкурировали.
6. **Лимиты.** Одна строка, до 1024 символов, без `<` и `>`. Реально хватает 300–700 символов.

## Плохо / хорошо

**Плохо:** `Помогает с changelog.`
Почему: нет «когда», нет синонимов, нет результата. Агент возьмёт его только на слове «changelog».

**Хорошо:**
`Собирает changelog и release notes из истории git: группирует коммиты по типам (фичи, исправления, breaking changes), пишет понятный пользователю текст в формате Keep a Changelog. Используй, когда пользователь просит changelog, заметки к релизу, «что изменилось с прошлой версии», подготовить релиз или описание версии — даже если он просто называет тег или диапазон коммитов.`

---

**Плохо:** `Этот скилл предназначен для того, чтобы агент мог эффективно и качественно выполнять задачи, связанные с обработкой данных.`
Почему: вода, ни одной сущности. Под это подходит любой запрос — и никакой.

**Хорошо:**
`Строит отчёты из CSV и Excel-выгрузок: чистит данные (пустые строки, форматы дат и сумм), считает итоги и динамику, выдаёт Markdown-отчёт с таблицами и графиками в PNG. Используй, когда пользователь даёт выгрузку из CRM, 1С, банка или таблицу и просит отчёт, сводку, итоги за период, «посчитай и покажи» — даже если файл называется непонятно.`

---

**Плохо:** `Используй всегда, когда пользователь работает с кодом.`
Почему: слишком широко — скилл будет срабатывать на всём и мешать.

## Проверка description

- Назови 5 запросов, на которых скилл должен сработать, и 3 близких, на которых не должен. Каждый «должен» покрыт словами из description? «Не должен» — не покрыт или исключён явно?
- Если агент на тестах не берёт скилл — добавь формулировки из этих запросов, а не капс.
- Если берёт лишнее — сузь сущности или добавь «не применяй для…».
