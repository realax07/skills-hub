# Тест-кейсы (evals/)

Формат совместим с `claude plugin eval`, но кейсы полезны и без него: это готовые сценарии
для ручного прогона «со скиллом / без» в любом агенте.

## Структура кейса

```
evals/<case-name>/
├── prompt.md          блок настроек + запрос пользователя
├── case.yaml          метаданные и ожидаемый результат
├── graders/
│   ├── 01-<что>.md    одно проверяемое утверждение
│   └── 02-<что>.md
├── files/             (опц.) входные файлы
└── place-files.sh     (опц.) кладёт files/ в рабочую папку теста
```

Создавай через `python3 scripts/new_eval.py` — он соберёт всё по формату, включая `files/` и `place-files.sh`.

### prompt.md

```
---
tags: [<скилл>]
max_turns: 30
timeout_seconds: 900
allowed_tools: [Read, Glob, Grep, Skill, Write, Edit, Bash]
---

<запрос пользователя>

Input files: <список, если есть files/>
```

В блоке настроек — только ключи, без свободного текста. Тяжёлым скиллам (браузер, сборка) поднимай `max_turns` и `timeout_seconds`.

### case.yaml

```yaml
schema_version: "1.1"       # строкой, в кавычках
name: <case-name>           # = имя папки
context:                    # только если есть files/
  scaffold_script: place-files.sh
expected_outcome: |
  Как выглядит хороший результат: 2–4 предложения о поведении и артефактах.
```

### graders/NN-*.md

```
---
type: llm
focus: trace
weight: 1
---

<одно утверждение о результате, которое можно проверить по трейсу и файлам>
```

## Как писать запросы

- **Как живой человек**: с контекстом, путями, сокращениями, иногда с опечатками. «вот выгрузка из црм в data/, сделай отчёт за 3 квартал, пустые строки выкинь».
- **Без имени скилла.** Тест проверяет и срабатывание тоже.
- **Разнообразие**: типичный случай, крайний случай (грязные данные, нет нужного файла, неоднозначность), и при возможности — запрос, где скилл должен принять решение сам (куда класть, что выбрать).
- 2–3 кейса достаточно на старте; добавляй кейс на каждый найденный баг.

## Как писать грейдеры

- **Одно утверждение — один грейдер.** «Отчёт содержит итоги по месяцам» и «пустые строки пропущены» — два файла.
- **Проверяемо по трейсу или файлам**: путь, наличие раздела, число элементов, вызов скрипта, сообщение пользователю.
- **Про результат, не про формулировки**: «отчёт содержит итог за сентябрь», а не «агент написал слово "сентябрь"».
- **Проверь, что скилл реально использован**, если это важно: «агент запустил validate перед ответом».
- **Негативные проверки** для крайних случаев: «исходные файлы в src/ не изменены».
- Субъективное (красиво ли, хороший ли тон) — не формализуй: смотри глазами.

## Плохо / хорошо

**Плохо:** запрос «Используй скилл csv-report для файла data.csv», грейдер «результат хороший».
**Хорошо:** запрос «вот выгрузка продаж, сколько заработали в сентябре и кто лучший менеджер?», грейдеры
«итог за сентябрь равен 1 284 500», «назван менеджер Иванова», «строки с пустой суммой пропущены и это упомянуто».
