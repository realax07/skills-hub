# Чек-лист перед сдачей скилла

Пройди после `validate_skill.py --strict --run-scripts`. Валидатор ловит формальное, этот список — смысловое.

## Срабатывание
- [ ] description: что делает + когда применять + синонимы и косвенные формулировки
- [ ] 5 запросов «должен сработать» покрыты словами из description, 3 соседних — нет
- [ ] Вся информация «когда» — в description, а не только в теле

## Тело
- [ ] Процесс — нумерованные шаги, в конце проверка результата и отчёт пользователю
- [ ] У каждого правила есть причина; нет капса вместо объяснений
- [ ] Строгий формат результата — точным шаблоном
- [ ] Таблица ресурсов: у каждого файла «когда открывать»
- [ ] Нет имён инструментов и путей одного агента; пути — относительно папки скилла

## Ресурсы
- [ ] `references/rules.md`: правила, крайние случаи, типичные ошибки
- [ ] `examples/`: полные результаты, хотя бы один «плохо / хорошо»
- [ ] `scripts/`: `--help`, `--json`, коды выхода, понятные ошибки; повторяющийся код вынесен
- [ ] Зависимости: `compatibility` + установщик с `--check`, установка вне папки скилла, пиннованные версии
- [ ] Пустые папки и неиспользованные шаблоны удалены (кроме `evals/`)

## Тесты
- [ ] 2–3 кейса, запросы как от живого человека, без имени скилла
- [ ] Есть крайний случай
- [ ] Грейдеры — по одному проверяемому утверждению

## Отчёт пользователю
- [ ] Путь к скиллу и дерево файлов
- [ ] Что делает каждый скрипт
- [ ] Как установить в агент(ы) и что скилл подхватится после перезапуска
- [ ] Что осталось сделать пользователю (если осталось)
