Авторство скиллов · skill-author

skill-author: из процесса — готовый скилл со структурой и тестами

Скилл превращает повторяющуюся задачу, промпт или диалог в скилл для код-агентов (Claude Code, Codex, OpenCode, Qwen и других с форматом Agent Skills): точный description, тело с процессом, правила и разборы, скрипты для детерминированного, шаблоны, тест-кейсы — и проверяет результат валидатором.

Что даёт

Хороший скилл — это не один длинный SKILL.md, а три уровня загрузки и код там, где модель каждый раз писала бы одно и то же.

Точный description

Что делает, когда применять (словами пользователя, с синонимами и косвенными запросами), «даже если…» и границы. До срабатывания агент видит только его.

Тело — про выполнение

Входные данные, шаги с развилками, правила с причинами, формат результата, пример, таблица ресурсов «когда открывать».

Ресурсы по уровням

references/ — подробные правила, examples/ — разборы плохо/хорошо, assets/ — шаблоны. Агент открывает их по ссылке, когда нужно.

Скрипты для повторяющегося

Парсеры, проверки, сборка — CLI с --help, --json и кодом ошибки. Суждение и вкус в скрипт не выносятся.

Тест-кейсы

evals/: 2–3 реалистичных запроса с грейдерами — видно, что скилл реально меняет поведение.

Под слабые модели

Точные команды, явные развилки и «спросить некого», механика в скриптах, текст вместо картинок, таблица «симптом → что делать».

Когда звать

Когда задачу будут повторять, а объяснять каждый раз не хочется.

Подходит

  • «Сделай из этого скилл», «научи агента делать X», «сохрани это как навык».
  • Превратить свой процесс, промпт, чек-лист или диалог в переиспользуемый скилл.
  • Разложить разросшийся SKILL.md, добавить скрипты, тесты или зависимости к скиллу.

Не подходит

  • Разовая задача, которую проще сделать сразу.
  • Правила одного проекта — им место в файле инструкций проекта (AGENTS.md и т.п.).

Скилл живёт: его ставят в агентов, гоняют на тестах и улучшают по тем же шагам.

Как результат используется потом

Агент

Видит description среди сотен других, решает, брать ли; потом выполняет тело и открывает ресурсы по ссылкам.

Автор

Улучшает скилл по провалам тестов и жалобам; валидатор держит структуру.

Примеры из прогонов

Из разобранного прогона «changelog по пятницам → скилл» (examples/01-workflow-to-skill.md).

Детерминированный разбор git log — в скрипт, текст для людей — инструкцией.

1. Понять: в диалоге пользователь уже поправлял — «не пиши хэши», «breaking changes отдельным разделом», «chore и ci не нужны»
2. Место: нужен и Claude, и Codex → ~/.agents/skills/
3. init_skill.py changelog-writer --dest ~/.agents/skills --script collect_commits
4. collect_commits.py <репо> [--since <тег>] --json — разбор типов, scope, BREAKING CHANGE
5. Шаблон разделов — assets/changelog.md; правила пользователя — references/rules.md с причинами
7. new_eval.py ×2 — репо с тегом; репо без тегов и с коммитами без типа
8. validate_skill.py … --strict --run-scripts → 0 ошибок

Полная структура, а не один SKILL.md.

changelog-writer/
├── SKILL.md
├── references/rules.md
├── examples/01-release.md
├── examples/02-noisy-history.md
├── scripts/collect_commits.py
├── assets/changelog.md
└── evals/
    ├── tagged-release/{prompt.md, case.yaml, graders/…}
    └── no-tags-messy-commits/{prompt.md, case.yaml, graders/…, files/, place-files.sh}

Главные правила

Почему скилл ведёт себя так, а не иначе.

  • Прогрессивная загрузка.Файл, о котором SKILL.md молчит, агент не откроет — у каждого ресурса явное «когда открывать».
  • Условия — в метаданных, выполнение — в теле.Тело грузится уже после решения: «когда применять» там только тратит контекст.
  • Объяснять почему, а не кричать.Модель, понимающая цель, сама справится с крайними случаями.
  • Общие принципы, не подгонка.Скилл вызовут на тысячах запросов; правило под один пример сломает остальные.
  • Агент-нейтрально и без сюрпризов.Без инструментов одного агента; никакой скрытой отправки данных.

Если что-то пошло не так

СимптомЧто делать
Скилл не срабатываетПереписать description: слова пользователя, синонимы, «даже если…» (references/description.md).
SKILL.md разроссяПроцесс оставить, правила — в references/, код — в scripts/ (examples/03-improve-bloated-skill.md).
Валидатор: заглушкиЗаполнить или удалить шаблонные файлы, кроме evals/.
Подробно для агента — SKILL.md. Гайд собран tools/build_guides.py из guide.json; правь его, а не этот файл.
