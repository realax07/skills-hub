# qa-scan

Переносит тест-кейсы из TMS в репозиторий так, чтобы дальше их вели в md, а агенты находили нужные кейсы под задачу.
Результат — папка `test-cases/` в корне проекта и указатель на неё в AGENTS.md:

```
test-cases/
  ROUTING.md                 # карта для агента: как найти кейсы под задачу, области, формат, как менять
  <раздел>/<подраздел>/      # иерархия TMS (сьюты, папки, секции) — папками
    INDEX.md                 # строка на кейс
    TC-0001-<slug>.md        # кейс: front-matter + Цель, Предусловия, Шаги, Постусловия, Параметры
  _shared/SS-001-<slug>.md   # общие шаги; в кейсе — ссылка, а не копия
  _attachments/TC-0001/      # вложения (если скачивали)
  _index/                    # by-capability, by-code, by-requirement, by-tag, by-autotest, index.json
  QUESTIONS.md               # секреты, ПДн, конфликты, несопоставленное — решает человек
  QUALITY.md                 # качество кейсов: дубли, размытое ожидаемое, нет шагов — для человека
  .source/                   # ids.json (номера TC ↔ id в TMS), config.json, redactions.json; snapshot.json не коммитится
```

**md первичен.** После переноса кейсы правят в репозитории; TMS — источник переноса. Поэтому у кейса свой постоянный номер `TC-0001`
(id TMS — только в `source`), формат держит `check.py`, а повторный импорт не затирает то, что правили в md.

Нужен только Python 3.9+. Всё, где можно ошибиться руками (разбор выгрузок, HTML → md, номера, индексы, поиск секретов), делают скрипты.
Модель решает: что спросить у человека, к какой возможности отнести спорные кейсы, что сообщить в отчёте.

## Как выполнять

Для любой модели: запускай команды как написано, `<skill>` — папка этого скилла, `<repo>` — корень репозитория проекта.
У каждого скрипта есть `--help`; не придумывай флаги. Скрипт упал — смотри «Если что-то не так», не обходи вручную.
Кейсы, индексы и вопросы не пиши руками и не «улучшай»: md-файлы делает `build.py`, правки полей сопоставления — `map.py`, новые кейсы — `new.py`.

Режимы — выбери по запросу:
- **A. Перенести из TMS** — первый импорт (шаги 1–9). По умолчанию.
- **B. Обновить из TMS** — «в TestRail поменяли кейсы, обнови» — раздел «Режим B».
- **C. Вести кейсы в md** — найти кейсы под задачу, добавить или поправить кейс — раздел «Режим C».

## Режим A: перенести из TMS

1. **Входные данные.** Пользователь рядом — спроси одним сообщением то, чего нет в запросе. Автономный прогон («меня не будет») —
   не спрашивай, бери умолчания из последнего пункта.
   - **TMS и откуда брать.** Ссылка на TMS → API: адрес, проект (TestRail — число из `index.php?/projects/overview/<id>`, Test IT — номер
     из `/projects/<номер>/tests`, Zephyr Scale — ключ проекта Jira, TestLink — имя проекта). Файл выгрузки → путь к нему.
     Как получить токен и как выгрузить файл в каждой TMS — [references/tms.md](references/tms.md).
   - **Записанные ответы API** (`--replay <папка>`, путь от текущей папки или абсолютный) — токен не нужен, сеть тоже.
   - **Токен — только переменной окружения:** `TESTRAIL_USER` + `TESTRAIL_KEY`, `TESTIT_TOKEN`, `ZEPHYR_TOKEN`, `TESTLINK_DEVKEY`.
     Попроси человека задать её в своём терминале перед запуском агента. Не проси прислать токен в чат и не пиши его в файлы:
     он попадёт в историю и в git. Токена нет — попроси файл выгрузки.
   - **Что переносить:** весь проект или ветку (`--section "Заказы/Отмена"`, `--tag smoke`). Большой проект (тысячи кейсов) — сначала
     пробный прогон `--limit 50`, посмотри результат, потом целиком.
   - **Язык заголовков** в кейсах: `--lang ru` (по умолчанию) или `en`. Текст кейсов не переводится.
   - **Спросить некого:** весь проект; язык — язык запроса; указатель — в найденный файл инструкций (`link.py --suggest`),
     а если их нет — создай `AGENTS.md`. Всё, что требует решения человека, — в `QUESTIONS.md` и в отчёт.

2. **Забрать кейсы** — одна команда, результат — `test-cases/.source/snapshot.json` (секреты уже скрыты):
   - API: `python3 <skill>/scripts/fetch.py api <repo> --tms testrail --url https://acme.testrail.io --project 3`
     (`--tms testit|zephyr|testlink`; Zephyr Cloud — без `--url`, Zephyr Data Center — `--url https://jira.acme.ru`;
     TestRail с несколькими сьютами — `--suite <id>` или все; вложения — `--attachments`).
   - Файл: `python3 <skill>/scripts/fetch.py file <repo> --file <выгрузка>` — формат определится сам; не определился — `--tms`.
     Таблица (CSV, xlsx) — сначала `python3 <skill>/scripts/fetch.py columns --file <выгрузка>`: если `title` или `steps` не нашлись,
     добавь `--map title="Наименование" --map steps="Шаги"` (те же `--map` — и в `fetch.py file`). TestLink — с `--prefix <префикс проекта>`.

3. **Прочитай сводку fetch.py:** сколько кейсов и шагов, сколько секретов скрыто (`S-01 пароль`…), найдены ли ПДн, какие поля TMS ушли в `custom`.
   Кейсов ноль или шагов подозрительно мало — не продолжай: проверь `--section`, `--map`, формат файла.

4. **Разложить в md:** `python3 <skill>/scripts/build.py <repo>` — кейсы, общие шаги, папки, индексы, `ROUTING.md`, блок импорта в `QUESTIONS.md`.

5. **Сопоставить с возможностями, кодом и автотестами** — это ключи роутинга:
   1. `python3 <skill>/scripts/map.py auto <repo>` — если в проекте есть `openspec/specs/` (скилл sa-scan), кейсы получают возможности
      по ключам требований и словам; автотесты в коде ищутся по номерам кейсов (`TC-0001`, `C123`, `SHOP-T12`, `WorkItemIds(…)`).
      Скрытые папки (`.opencode`, `.claude`…) и папки скиллов не сканируются; найденные автотесты при каждом запуске пересчитываются.
      Спеки нет — шаг про возможности пропускается, роутинг будет по папкам, требованиям, тегам и коду; в отчёте предложи sa-scan.
      **Просмотри назначения в выводе** (строки `TC-… → возможность (слова: …)`): по названию кейса и возможности ошибка видна сразу.
      Неверное — `map.py set <repo> TC-… --cap <верная> --replace` или `--clear-cap`. Неверный автотест — `map.py set <repo> TC-… --clear-autotests`.
   2. `python3 <skill>/scripts/map.py list <repo> --unmapped` — что осталось, по папкам. `python3 <skill>/scripts/map.py caps <repo>` — список возможностей.
   3. Реши по смыслу: папка целиком об одной возможности — `map.py set <repo> --section <папка> --cap <возможность>`;
      отдельные кейсы — `map.py set <repo> TC-0012 TC-0013 --cap <возможность>`; кейс о двух возможностях — две `--cap`.
      Не уверен — оставь без возможности: неверная возможность хуже пустой, она уводит агента не к тем кейсам.
   4. Знаешь, какой код проверяет кейс (из автотеста, из шагов с путями API), — `map.py set <repo> TC-… --code src/routes/orders.ts`.

6. **Качество:** `python3 <skill>/scripts/lint.py <repo>` → `QUALITY.md`. Кейсы не переписывай: это решение владельцев тестов.
   Возьми из отчёта 3–5 главных цифр для итога.

7. **Указатель:** `python3 <skill>/scripts/link.py <repo> --suggest`, затем `python3 <skill>/scripts/link.py <repo> --file AGENTS.md`
   (или файл из подсказки; файла нет — `link.py` создаст его). Без указателя агенты проекта не узнают, что кейсы есть.
   `fetch.py` предупредил, что выгрузка лежит в репозитории с секретами, — скажи человеку в отчёте: не коммитить её, а если уже в git —
   убрать из истории и сменить пароли и токены.

8. **Проверка:** `python3 <skill>/scripts/check.py <repo>` — готово, когда `ошибок 0`. Ошибка «похоже на секрет» — значение, которое
   маскировка не узнала: замени в кейсе на `[скрыто: S-NN]` или ссылку на переменную окружения и добавь вопрос в `QUESTIONS.md` вне блоков `qa:auto`.

9. **Отчёт человеку** (коротко): откуда и сколько перенесено (кейсов, шагов, общих шагов, папок); сколько сопоставлено с возможностями
   и автотестами; скрытые секреты и что с ними решить; ПДн; главное из `QUALITY.md`; что коммитить (всё в `test-cases/`,
   кроме того, что в `.source/.gitignore`); что дальше — режим B для обновления, режим C для работы с кейсами.
   Не коммить без просьбы пользователя.

## Режим B: обновить из TMS

Нужен, пока команда переезжает: в TMS ещё что-то меняют, а в md уже правят.
1. `fetch.py` с теми же параметрами, что в первый раз (они в `test-cases/.source/config.json`); новая выгрузка может называться иначе —
   передай её путь в `--file`, `config.json` обновится сам.
2. `python3 <skill>/scripts/build.py <repo> --dry-run` — что изменится: новые, обновлённые, перенесённые, правленные в md, конфликты, исчезнувшие из TMS.
3. `python3 <skill>/scripts/build.py <repo>`. Кейс, который не правили в md, обновится; правленный — останется как есть.
   Правили и там и там — **конфликт**: версия TMS лежит в `test-cases/.source/incoming/<id>.md`. Покажи человеку разницу и спроси;
   решение — `build.py <repo> --accept <id>` (взять TMS, правки в md пропадут) или `--keep <id>` (оставить md). Сам не выбирай:
   правку в md мог сделать человек намеренно.
4. Исчезнувшие из TMS кейсы не удаляются (md первичен) — они в `QUESTIONS.md`. Дальше `map.py auto`, `lint.py`, `check.py`, как в режиме A.

## Режим C: вести кейсы в md

- **Найти кейсы под задачу:** `python3 <skill>/scripts/route.py find <repo> --cap <возможность>` · `--path src/routes/orders.ts` ·
  `--req SHOP-12` · `--tag smoke` · `--text "отмена оплаченного"` · `--section otmena-zakaza` (фильтры складываются; `--json`).
  Без скилла агенты проекта ищут так же по `ROUTING.md` и `_index/` через grep — это и записано в указателе.
- **Новый кейс:** `python3 <skill>/scripts/new.py <repo> --title "…" --section "Отмена заказа/Менеджер" [--cap …] [--req …] [--priority high]`
  — следующий свободный номер (номера не переиспользуются), каркас со статусом `draft` и местами «заполнить».
- **Правка кейса:** меняй шаги, ожидаемое, поля front-matter по формату [references/format.md](references/format.md); id и имя файла не меняй.
  Устарел — `status: deprecated`.
- **После правок:** `python3 <skill>/scripts/route.py index <repo>` и `python3 <skill>/scripts/check.py <repo>` (без ✗).

## Ключевые правила

- **Перенос, а не переписывание.** Текст шагов и ожидаемого — как в TMS, даже если он плохой: «Работает» остаётся «Работает»,
  а попадает в `QUALITY.md`. Агент, который «улучшил» кейс, тихо меняет то, что проверяют люди.
- **Секреты не покидают TMS.** Пароли, токены, ключи, реальные карты скрываются в `fetch.py` до записи на диск (`[скрыто: S-01]`, одно значение —
  один номер); в `QUESTIONS.md` — где они были, без значений. Тестовые карты (4242…) и адреса example.com остаются. Сырые ответы API (`--record`)
  держи вне репозитория.
- **Токен — переменной окружения, не в чат.** Иначе он окажется в истории переписки, логах и, возможно, в git.
- **Номер кейса постоянный.** `TC-0001` не меняют и не переиспользуют: на него ссылаются автотесты, задачи и другие кейсы.
- **Сопоставление — с осторожностью.** Неуверенно — без возможности. Пустое поле видно в отчёте и в `QUESTIONS.md`, а неверное — нет.
- **Правки в md важнее TMS.** Повторный импорт не перезаписывает правленные кейсы; конфликт решает человек.
- Полный свод, крайние случаи и что коммитить — [references/rules.md](references/rules.md).

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `нет переменной окружения …` | Попроси человека задать её в своём терминале и перезапустить; нет токена — файл выгрузки |
| `TMS отказала в доступе (401/403)` | Неверный токен или нет прав на проект — скажи человеку; не перебирай варианты авторизации |
| `не найдено (404)` | Проверь `--url` (TestRail — без `/index.php`, Test IT — корень сайта) и `--project`; см. [references/tms.md](references/tms.md) |
| `не нашёл колонку с названием кейса` | `fetch.py columns --file …`, затем `--map title="<колонка>"` |
| `не узнал формат XML` | Укажи `--tms`; если формат всё равно не разбирается — попроси выгрузку в другом формате (CSV/xlsx идут через `--tms table`) |
| Кейсов 0 после `--section` | Путь разделов — как в TMS, через `/`; посмотри `test-cases/.source/snapshot.json` без фильтра |
| Шаги слиплись в один | Таблица со шагами в одной ячейке без нумерации — так и было в TMS; не дели вручную, отметь в отчёте |
| `check.py`: «индексы устарели» | `route.py index <repo>` |
| `check.py`: «похоже на секрет» | См. шаг 8 режима A |
| `check.py`: `ссылка … никуда не ведёт` | Общий шаг или вложение не перенесены — догрузи (`--attachments`, весь проект) или убери ссылку и скажи в отчёте |
| `build.py`: конфликты | Режим B, шаг 3: спроси человека, `--accept` или `--keep` |
| Возможности все не те | `map.py set … --cap … --replace`; эвристика путается, если в спеке мало слов — не страшно, решает модель |
