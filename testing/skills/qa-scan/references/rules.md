## Обязательные правила

1. **Текст кейсов переносится как есть.** Не переписывай шаги, не дописывай ожидаемое, не объединяй дубли, не переводи.
   Почему: кейсы — договорённость команды о том, что проверять; агент, который «причесал» 500 кейсов, незаметно поменял смысл десятков.
   Плохие кейсы видны в `QUALITY.md` — решение за людьми.
2. **Секреты скрываются до записи на диск** (`fetch.py` делает это сам). Значения не пишутся ни в md, ни в снимок, ни в отчёт, ни в чат.
   Почему: репозиторий читают все, у кого есть доступ к коду, и он живёт годами в истории git. Если маскировка что-то пропустила
   (`check.py` ловит пароли, токены, ключи, реальные карты) — скрой вручную и запиши вопрос.
3. **Токены — только из переменных окружения.** Не проси человека прислать токен, не пиши его в файлы и команды в отчёте.
   Почему: переписка и логи агента сохраняются; токен даёт доступ ко всей TMS.
4. **Номер `TC-NNNN` постоянный.** Не переименовывай файлы с другим номером, не переиспользуй номера удалённых кейсов.
   Почему: на номер ссылаются автотесты (`TC-0004` в аннотации), задачи и другие кейсы; новый смысл под старым номером ломает связи молча.
5. **Правки в md не затираются.** Конфликт импорта решает человек (`--accept` / `--keep`), не агент.
   Почему: после переезда md первичен; правка могла быть намеренной.
6. **Сопоставление — только уверенное.** Возможность ставь, когда кейс явно о ней (по названию, разделу, требованию, шагам).
   Почему: неверная возможность уводит агента доработки к не тем кейсам и прячет кейсы от правильного поиска; пустая — видна в отчёте.
7. **Служебные файлы — только скриптами.** `ROUTING.md`, `INDEX.md`, `_index/`, блоки `qa:auto` в `QUESTIONS.md` пересобираются.
   Почему: правка руками пропадёт при следующей сборке, а индексы разойдутся с кейсами.

## Рекомендации

- Большой проект — сначала `--limit 50`, посмотри 3–5 кейсов разных разделов: шаги разбились, приоритеты нормализовались, секреты скрыты.
  Потом целиком. Тысячи кейсов — нормально: скрипты не читают кейсы моделью.
- Есть `openspec/` (sa-scan) — обязательно `map.py auto`: связь «возможность → кейсы» — главный ключ для агентов доработки.
  Нет спеки — предложи человеку сначала sa-scan, но импорт не блокируй.
- При ручном сопоставлении решай по папкам: обычно раздел TMS = одна возможность (`map.py set --section`), исключения — по одному.
- Если в кейсах есть пути API или экраны, а в репозитории их обработчики — `map.py set --code`: это ключ для `by-code.md`.
- В отчёте приводи числа, а не впечатления: «скрыто 3 секрета, 12 кейсов без ожидаемого результата, 2 пары дублей».

## Что коммитить

Всё в `test-cases/`, кроме того, что в `test-cases/.source/.gitignore` (`snapshot.json`, `incoming/`, `files/`).
`ids.json` коммитить обязательно: без него повторный импорт выдаст кейсам новые номера.
Вложения (`_attachments/`) — по решению человека: картинки бывают тяжёлыми и могут содержать данные клиентов.

## Крайние случаи

| Ситуация | Что делать | Почему |
|---|---|---|
| Токена нет, человек недоступен | Работай по файлу выгрузки, если он есть; иначе остановись и напиши, что нужно | Без доступа и файла переносить нечего, угадывать нельзя |
| Кейсы в одной ячейке без нумерации шагов | Оставь одним шагом, отметь в отчёте | Делить по смыслу — переписывание |
| Скрытый секрет нужен тесту | Предложи переменную окружения (`$SHOP_ADMIN_PASSWORD`) — заменить `[скрыто: S-NN]` на неё может человек или агент по его слову | Значение в репозитории — утечка; ссылка — нет |
| ПДн (телефоны, email) в тестовых данных | Не скрываются по умолчанию — вопрос в `QUESTIONS.md`; реальные люди → `fetch.py … --mask-pii` и `build.py` | Чаще это тестовые данные, но решать человеку |
| Два проекта TMS в один репозиторий | Второй импорт в тот же `test-cases/` не делай: снимок и номера общие, второй fetch заменит первый. Спроси человека: объединить проекты в TMS, перенести второй в другой репозиторий или позже | Слой рассчитан на один источник |
| Кейс удалён в TMS | Остаётся в md, вопрос в `QUESTIONS.md`; не удаляй сам | md первичен |
| Раздел переименовали в TMS | Не правленный в md кейс переедет в новую папку сам; правленный останется на месте | Перемещение правленого файла — тоже правка |
| Картинки в шагах ссылаются на TMS | Не скачивай по ссылкам руками; `--attachments` только для вложений кейса; опиши проблему в отчёте | Без входа картинки недоступны, а модели без зрения их не увидят |
| Возможностей в спеке нет под раздел кейсов | Оставь без возможности; в отчёте: «кейсы раздела X не покрыты спекой» | Это пробел спеки, а не кейсов |
| Человек просит «сразу улучшить кейсы» | Сначала перенос как есть, отдельным шагом правки по `QUALITY.md` с его согласием, видимым диффом | Разделение переноса и правки сохраняет проверяемость |

## Типичные ошибки

- **Попросить токен в чат** → попросить задать переменную окружения в терминале человека.
- **Написать кейсы руками по ответу API** → только `fetch.py` + `build.py`: иначе нет секретов-масок, хешей и номеров.
- **«Привести к единому стилю» шаги** → перенос как есть, замечания — в `QUALITY.md`.
- **Поставить возможность всем кейсам раздела, где половина о другом** → `--section` для однородных папок, остальные по одному или пусто.
- **Удалить кейсы, исчезнувшие из TMS** → вопрос человеку.
- **Разрешить конфликт импорта самому** → показать разницу и спросить.
- **Положить `--record` в репозиторий** → сырые ответы содержат секреты; папка — вне репозитория.
