# Пример 1. Выгрузка TestRail → test-cases/ в проекте со спекой sa-scan

Прогон на фикстуре `evals/files/shop` (сервис заказов: `openspec/specs/` из sa-scan, `system-context/trace.md`, тесты vitest)
и выгрузке `evals/files/exports/testrail-shop.xml` (8 кейсов, три уровня секций, пароль и JWT в шагах, дубль, «Работает» в ожидаемом).

## Запрос

> вот выгрузка из testrail exports/testrail-shop.xml, перенеси тесты в репо чтобы агенты их видели. спека у нас уже есть в openspec

## Ход работы

Входные данные есть все (файл, репозиторий, спека) — вопросов нет, язык — русский.

```bash
python3 <skill>/scripts/fetch.py file . --file exports/testrail-shop.xml
```
```

  ПДн найдено: 1 (не скрыты — вопрос в QUESTIONS.md)
  поля TMS, ушедшие в custom: component (1)
```
Кейсов и шагов столько, сколько ждали, — продолжаем.

```bash
python3 <skill>/scripts/build.py .
python3 <skill>/scripts/map.py auto .
```

верно (лимит позиций — требование оформления). Автотесты нашлись по аннотациям `@testrail C101` и `[C110]` в названии теста.

```bash

python3 <skill>/scripts/link.py . --suggest        # файлов инструкций нет → создать AGENTS.md
python3 <skill>/scripts/link.py . --file AGENTS.md
python3 <skill>/scripts/check.py .
```

## Отчёт человеку

> Перенёс 8 кейсов (14 шагов) из TestRail «Магазин — регресс» в `test-cases/`: 3 раздела, 5 папок. Все 8 привязаны к возможностям
> из `openspec/` (оформление 3, отмена 3, отгрузка 2), у 3 найдены автотесты в `test/orders.test.ts`. **У `order-payment` и
> `order-viewing` нет ни одного кейса** — оплата и просмотр заказов проверяются только косвенно.
>
> Что решить вам (`test-cases/QUESTIONS.md`): в шагах были 2 пароля и токен — они скрыты (`S-01…S-03`); откуда тест должен брать
> настоящие значения? В TC-0006 телефон поддержки — тестовый или реальный?
>
> Качество (`QUALITY.md`): TC-0007 и TC-0008 — дубли, в TC-0003 ожидаемое «Работает», в TC-0006 картинка ссылкой на TestRail.
> Кейсы я не менял.
>
> Коммитить всё в `test-cases/` (кроме того, что в `.source/.gitignore`) и `AGENTS.md`. Не коммитил.

## Почему так

- Ни одного кейса руками: md, номера, хеши, индексы — скрипты; модель только проверила назначения и написала отчёт.
- Пробел покрытия (`order-payment` — 0 кейсов) виден сразу в `ROUTING.md` → «Возможности» — это ценнее, чем пересказ всех кейсов.
- Дубли и размытое ожидаемое названы, но не исправлены: это решение владельцев тестов.
