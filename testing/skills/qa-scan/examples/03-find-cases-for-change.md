# Пример 3. Какие кейсы обновить под изменение поведения (режим C)

Слой `test-cases/` уже перенесён (пример 1), в проекте есть `openspec/` и `system-context/trace.md`.

## Запрос

> меняем правило: покупатель теперь может отменить оплаченный заказ сам, деньги возвращаются автоматически. какие тест-кейсы надо поправить и каких не хватает?

## Ход работы

Изменение — о возможности `order-cancellation` и о коде `src/routes/orders.ts` (отмена). Ищем по обоим ключам и словами:

```bash
python3 <skill>/scripts/route.py find . --cap order-cancellation
python3 <skill>/scripts/route.py find . --text "отменить оплаченный возврат"
```
```
TC-0006  highest ready  test-cases/otmena-zakaza/menedzher/TC-0006-…md  — Менеджер отменяет оплаченный заказ с возвратом  [cap]
TC-0004  high    ready  test-cases/otmena-zakaza/pokupatel/TC-0004-…md  — Покупатель не может отменить оплаченный заказ  [cap]
TC-0005  medium  ready  test-cases/otmena-zakaza/pokupatel/TC-0005-…md  — Отмена неоплаченного заказа  [cap]
найдено: 3
```
Читаем три кейса целиком (они короткие). `--path src/routes/orders.ts` дал бы все 8 — этот файл обслуживает несколько возможностей,
поэтому начинаем с возможности, а путь — для проверки, что ничего не упустили.

## Результат

> - **TC-0004** «Покупатель не может отменить оплаченный заказ» — противоречит новому правилу. Предлагаю переписать шаги: отмена
>   PAID покупателем → REFUNDED и возврат в Stripe; ожидание 409 убрать. Автотест `test/orders.test.ts:8` («customer cannot cancel
>   paid order») тоже придётся поменять.
> - **TC-0006** (менеджер, возврат) — не меняется, но стоит проверить, что возврат один и тот же механизм.
> - **TC-0005** (отмена NEW) — не затронут.
> - **Не хватает:** отмена оплаченного покупателем после отгрузки (SHIPPED) — что должно быть? Могу завести каркас:
>   `new.py . --title "Покупатель отменяет оплаченный заказ с возвратом" --section "Отмена заказа/Покупатель" --cap order-cancellation`.
>
> Правки кейсов внесу, когда подтвердите правило для SHIPPED; после — `route.py index .` и `check.py .`.

## Почему так

- Сначала ключ возможности, потом слова, а не чтение всех кейсов подряд: на тысячах кейсов это единственный путь, который влезает в контекст.
- Кейс, который противоречит новому правилу, меняют вместе с кодом — иначе регресс по кейсам «упадёт» на правильном поведении.
- Чего не хватает — предложено с готовой командой, а не написано молча: новый кейс — договорённость, её подтверждает человек.
