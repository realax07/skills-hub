## Тест-кейсы

Ручные и автоматизированные тест-кейсы — в `test-cases/` (md первичен: кейсы правят здесь, а не в TMS).

**Перед правкой поведения, интерфейса или API — по шагам:**

1. Открой `test-cases/ROUTING.md`: там таблица «как найти кейсы под задачу».
2. Найди кейсы: по возможности — `test-cases/_index/by-capability.md`; по файлу кода — `grep -n "<путь>" test-cases/_index/by-code.md`; по ключу задачи — `grep -n "<КЛЮЧ>" test-cases/_index/by-requirement.md`;
   по словам — `grep -ril "<слово>" test-cases --include="TC-*.md"`.
3. Прочитай найденные кейсы: шаги и «Ожидается» — это то, что не должно сломаться. Регресс после правки — по ним.
4. Поведение изменилось намеренно — сначала спека (если есть `openspec/` — через `openspec/changes/`), потом кейсы:
   кейс с ставшим неверным ожиданием правь на месте (тот же id); новый сценарий — новый кейс со следующим номером TC
   (id не меняй и не переиспользуй). Устарел — `status: deprecated`. Со скиллом qa-scan поиск — `route.py find`.
5. `[скрыто: S-NN]` — секрет: не вписывай значение, бери из окружения.
6. `test-cases/_index/`, `INDEX.md` и `ROUTING.md` руками не правь — их пересобирает qa-scan (`route.py index`, `check.py`).
