# Три разных варианта доработки

Три варианта — это три **разных сценария** для одной задачи, а не одна раскладка в трёх оттенках. Всё — в рамках
существующей системы: те же цвета, шрифты, канон деталей. Различаются UX-паттерн, композиция и то, **как** используется палитра.

## Оси различия

| Ось | Обязательно | Примеры значений |
|---|---|---|
| Подход (UX) | **да, у всех трёх разный** | сравнение рядом / таблица / переключатель; одна форма / мастер по шагам / встроенное редактирование |
| Композиция | хотя бы у двух разная | колонки и сетка; плотно или воздушно; что крупно — цифра, заголовок, картинка |
| Палитра | хотя бы у одного другая | светлая подложка / тёмная секция (если тёмные фоны есть на сайте) / акцентная плашка; где основной цвет |

Палитра — только из контекста: «тёмная секция» допустима, если тёмный фон уже есть в `foundations.md` (футер, герой) — возьми его переменную.

## Паттерны по типу доработки

Возьми три **разные** строки-подхода для своего типа; не нашёл тип — по аналогии с ближайшим.

| Доработка | Подход 1 | Подход 2 | Подход 3 |
|---|---|---|---|
| Тарифы, планы | карточки рядом, рекомендуемая выделена | таблица сравнения возможностей | переключатель (месяц/год или сегмент) + одна крупная карточка |
| Форма (заявка, регистрация) | одна короткая форма в строку/колонку | мастер по шагам с прогрессом | форма рядом с пояснением/выгодами (две колонки) |
| Список объектов (заказы, статьи) | таблица с сортировкой | карточки-сетка | список-деталь: слева список, справа выбранный |
| Фильтры, поиск | боковая панель фильтров | чипы над списком | одна строка поиска + «ещё фильтры» во всплывающем |
| Пустое состояние | иллюстрация/иконка + одно действие | чек-лист первых шагов | пример-заглушка данных с призывом заменить |
| Призыв к действию (CTA-блок) | широкая плашка на акцентном фоне | две колонки: довод + форма | тихая строка в потоке текста со ссылкой-кнопкой |
| Отзывы, доверие | одна крупная цитата | сетка коротких цитат | логотипы/цифры строкой (только данные из задачи) |
| Настройки | одна длинная страница с разделами | вкладки по разделам | список настроек с редактированием по месту |
| Онбординг, подсказки | модалка-мастер | встроенный чек-лист на странице | подсказки у элементов по очереди |
| Карточка товара/объекта | галерея слева, покупка справа | крупное фото сверху, детали ниже | компактная карточка + раскрывающиеся детали |
| FAQ, справка | аккордеон | две колонки вопрос-ответ | поиск по вопросам + популярные |

## Как mock.mjs меряет различие

На отрисованном блоке (десктоп 1440) считаются: число колонок в главной сетке, есть ли таблица, есть ли переключатели
(вкладки, радио, чекбоксы, select, details), доля тёмного фона и акцентного фона, высота и число действий.
Пара вариантов совпадает по признаку:

- **структура** — то же число колонок, таблица и переключатели одинаково есть/нет;
- **палитра** — доля тёмного отличается меньше чем на 15%, акцента — меньше чем на 10%;
- **объём** — высота отличается меньше чем на 15% и действий почти столько же.

Два совпадения из трёх — `✗ похожи` (переделай один вариант по другой строке таблицы паттернов), одно — `!`.
PLAN.md тоже проверяется: заполнен, у каждого варианта свой «Подход (UX)».

## Типичные ошибки

- **Три карточки, три цвета кнопок** → это один вариант; меняй паттерн (таблица, переключатель), а не оттенок.
- **Новый цвет «для выразительности»** → check.mjs поймает; новая палитра — решение владельца (или wd-forge).
- **Блок на пустом листе** → мокап собирается в странице эталона: видно, как блок стоит рядом с соседями.
- **Выдуманные цифры и отзывы** → только данные из задачи, иначе пометка «пример».
- **Сразу в код** → сначала выбор пользователя; реализация — только выбранного.
