# Пример 2: элемент без канона и «новый акцентный цвет»

## Запрос

> Сделай на странице тарифов переключатель «помесячно / за год», и пусть годовая цена подсвечивается зелёным, чтобы было видно выгоду.

В контексте: позиция `normalize`; переключателей и табов нет ни в `parts/`, ни в `source.md`; зелёного в палитре нет.

## Плохо

Сверстать переключатель «как обычно делают»: серый трек `#e5e5e5`, белый ползунок с тенью `0 1px 3px rgba(0,0,0,.3)`,
шрифт системный 14px; годовую цену — `color: #16a34a`. Проверку не запускать: «элемент новый, сравнивать не с чем».

Почему плохо:
- Три новых цвета и новая тень — по сути новая мини-дизайн-система внутри фичи. Следующий агент возьмёт её за образец.
- Зелёный — решение владельца о палитре, а не о фиче. Принято молча.
- Без проверки не видно, что шрифт браузерный, а не шрифт сайта.

## Хорошо

1. `brief.mjs --path /pricing --groups buttons,badges` и поиск в `parts/components.md`, `source.md` → «Компоненты»:
   переключателя нет. Значит, собирать из токенов.
2. Сборка по аналогии: две кнопки-сегмента; активная — как «Кнопка основная» (фон var(--color-primary), белый текст),
   неактивная — как «Кнопка контурная»; радиус 10px (`--radius-md`), шрифт наследуется.
3. Зелёный: пользователь доступен — вопрос до вёрстки: «Зелёного в палитре нет. Добавить новый цвет (это решение о дизайн-системе)
   или подсветить выгоду существующим — бейджем «−20%» (жёлтый `.badge`)?» Ответ: «бейджем».
   Если бы спросить было некого — бейдж и пометка в отчёте.
4. `check.mjs --url http://localhost:5173/pricing --selector ".billing-toggle" --changed`:
   ```
   ✗ кнопка «помесячно» — новый вариант, такого на сайте нет (1 эл.)
       → ближайший канон: Кнопка контурная `dfvh5f` (parts/buttons.md) — отличие: радиус 0px вместо 10px; отступы 8/16 вместо 12/20
   ```
   Радиус и отступы исправлены — сегменты совпали с каноном, остался «новый вариант» только у контейнера-трека: ожидаемо.

## Результат (сообщение пользователю)

```
Переключатель «помесячно / за год» — src/components/BillingToggle.tsx, на странице тарифов над карточками.
Канона переключателя в дизайн-контексте нет: собран из канонических кнопок (активная — основная, неактивная — контурная).
Выгода годового тарифа — существующим бейджем «−20%», новый зелёный не вводил (как договорились).
check.mjs: 0 нарушений по цветам и шрифтам; «новый вариант» — только трек переключателя, это новый элемент.
После слияния стоит переснять страницу тарифов и разметить переключатель в разборе деталей.
```

## Почему так

- Нет канона — не значит «свобода»: токены и ближайшие детали задают границы.
- Новый цвет — вопрос владельцу; альтернатива из существующего почти всегда есть.
- Проверка нужна и для нового элемента: она отделяет ожидаемый «новый вариант» от реальных ошибок (цвет, шрифт).
