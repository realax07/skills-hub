# Пример 2: рабочий интерфейс — «три оттенка одного» против трёх направлений

## Запрос

> Нужен дизайн кабинета для нашей CRM для клиник: запись пациентов, расписание врачей. Покажи варианты.

## Плохо

Сразу сверстать три дашборда «как обычно»: сайдбар слева, четыре карточки показателей, таблица, график.
Варианты отличаются цветом сайдбара (синий, зелёный, фиолетовый) и радиусом карточек. Шрифт — Inter во всех трёх,
заголовки карточек с иконкой в цветной плитке, фиолетово-синий градиент на главной метрике. Для «живости» —
шрифт Unbounded в заголовках и fade-up на каждой карточке.

Почему плохо:
- Это один вариант в трёх цветах: выбирать не из чего, обсуждение уйдёт в «а зелёный посветлее».
- Шаблонные приёмы (Inter, плитки с иконками, градиент) — `lint.mjs` даст ✗ и ! на каждом экране.
- Игривый шрифт и анимации в рабочем интерфейсе мешают работе: смелость не по режиму.

## Хорошо

1. Бриф: режим `operate` (главная задача — быстро записать пациента), экраны: «очередь записи» и «карточка записи».
2. `deal.mjs --out design-forge --mode operate --product "CRM для клиник"` — скрипт сам ограничивает плотность,
   движение и игривые шрифты для рабочего режима:
   ```
   язык шрифтов: с кириллицей · темы: две (data-theme) · отрасль: Медицина, клиники, здоровье (правила — в PLAN.md)
   A: Редактор-полотно · Ночной лес (dark) · Wix Madefor Display / Wix Madefor Text
   B: Входящие · Баклажан (dark) · Bitter / Fira Sans
   C: Расписание · Монохром (light) · EB Garamond / Fira Sans
   ```
   «Редактор-полотно» — сценарий для создания макетов, а регистратура записывает пациентов: `deal.mjs --reroll a` →
   «Пошаговый мастер» (Tektur / Geologica). Две темы — у каждого направления: тёмная основная получила выведенную светлую
   и наоборот, переключение `data-theme`.
3. Планы: у «Мастера» — запись в три шага (пациент → врач и время → подтверждение); у «Входящих» — заявки разбираются
   по одной с превью и быстрыми действиями; у «Расписания» — сетка врачей по времени. Сценарии разные.
   Отраслевые правила в каждом плане: спокойствие, крупный текст, ясные состояния форм.
4. Мокапы со всеми состояниями: пустая очередь, ошибка записи, загрузка. UI-кит у каждого — с таблицей, вкладками, диалогом
   и опасной кнопкой (для `operate` они обязательны). Lint в обеих темах: 0 ошибок, различие ✓.

## Результат

Пользователь выбирает не цвет, а **способ работы** регистратуры: поток (доска), обзор (командный центр) или очередь
(список и деталь). Утверждённый вариант → `design-context/` → остальные экраны кабинета делает wd-fit.

## Почему так

- Разность по архетипу (сценарию) важнее разности по цвету — особенно в рабочем интерфейсе.
- Режим `operate` удержал смелость там, где она уместна: в деталях, а не в шрифтах и анимации.
- `--reroll` заменил одно неподходящее направление, не трогая два удачных.
