# Гайд по слою архитектуры

Слой собирает ar-scan: системы за рамками одного проекта, связи между ними и контракты, у которых есть потребители в других системах.

## Что где

| Файл | Что там | Когда открывать |
|---|---|---|
| `landscape.md` | системы, схема, связи «A → B» с назначением, общая инфраструктура, документы, ADR | обзор, «кто с кем связан» |
| `systems/<id>.md` | карточка системы (~3 тыс. токенов): кто её вызывает и слушает, кого вызывает она, события, общие данные, расхождения | изменение в этой системе |
| `contracts.md` | события, HTTP и gRPC с потребителями в других системах: владелец, потребители, поля | меняешь контракт |
| `landscape.json` | то же для скриптов (sa-change, проверки) | из кода |
| `RECONCILE.md` | расхождения кода и документов с решениями | сверка, ревью |
| `QUESTIONS.md` | открытые вопросы | человеку |
| `sources.json` | репозитории, документы, настройки систем — правится только командами `landscape.py` | — |

## Как пользоваться при изменении

1. Открой карточку системы, которую меняешь: `systems/<id>.md`.
2. Меняется вход или событие — найди его в `contracts.md`: есть потребители в других системах — это пункт влияния,
   каждый потребитель — решение (задача у его владельца или «не затрагивается: почему»).
3. Общая база данных с другой системой — изменение схемы согласуется с ней.
4. Чего нет в слое — вопрос в `QUESTIONS.md`, а не догадка: слой видит только добавленные репозитории и документы.

## Обновление

`landscape.py status <arch>` — что изменилось с последней сборки; `landscape.py build <arch>` — пересобрать
(заметки вне блоков и решения в RECONCILE.md сохраняются); `landscape.py link <arch> <repo>` — обновить копию карточек в проекте.
