# Пример 1: ADR и страница стандартов → принципы и нарушения

Ландшафт клиники собран ar-scan: booking (Go), billing (Java), reminders (Python), SMS-шлюз внешний. Документы: `adr/0003-async-integration.md`,
выгрузка Confluence «Стандарты разработки». Запрос: «Сделай из этого правила для агентов и проверь, кто их уже нарушает».

## Кандидаты

`rules.py scan architecture` нашёл 9 кандидатов. Решения:

**Плохо:**

```
- [x] K-02 «Сервисы должны быть отказоустойчивыми и масштабируемыми.» — confluence/standards.html:8
  - **Решение:** принцип P-02
- [x] K-05 «Мы стараемся покрывать тестами новые сценарии.» — confluence/standards.html:31
  - **Решение:** принцип P-05
- [x] K-07 «Счёт выставляется после приёма врача.» — adr/0003-async-integration.md:14
  - **Решение:** принцип P-07
```

«Отказоустойчивыми» — лозунг: проверить нечем, агент его проигнорирует. Тесты — пожелание. Счёт после приёма — поведение billing,
это ландшафт и спека, а не правило для всех систем. Три таких «принципа» — шум в каждом плане sa-change.

**Хорошо:**

```
- [x] K-02 «Сервисы должны быть отказоустойчивыми и масштабируемыми.» — confluence/standards.html:8
  - **Решение:** не принцип: общий лозунг без проверяемой границы; проверяемая часть — таймауты, она в K-03 → P-02
- [x] K-03 «Внешний вызов должен иметь таймаут не больше 3 секунд и не больше двух повторов.» — confluence/standards.html:9
  - **Решение:** принцип P-02
- [x] K-05 «Мы стараемся покрывать тестами новые сценарии.» — confluence/standards.html:31
  - **Решение:** не принцип: пожелание, нарушение ничего не ломает
- [x] K-07 «Счёт выставляется после приёма врача.» — adr/0003-async-integration.md:14
  - **Решение:** не принцип: поведение billing — в ландшафте и спеке billing
```

```
python3 <skill>/scripts/rules.py add architecture --title "Таймаут внешних вызовов не больше 3 секунд" \
  --rule "Каждый внешний HTTP-вызов задаёт таймаут не больше 3 секунд и не больше двух повторов." \
  --why "Повисший SMS-шлюз иначе держит запись к врачу: пациент видит ошибку, хотя приём создан." \
  --area надёжность --applies http --source confluence/standards.html:9 --check timeout --max 3
```

## Нарушения

`rules.py verify architecture`:

```
- [ ] V-01 `reminders`: таймаут 30 с больше лимита 3 с
  - Где: reminders:reminders/sms.py:22 `requests.post(SMS_URL, json=payload, timeout=30)`
- [ ] V-02 `billing`: внешний вызов без таймаута (лимит 3 с)
  - Где: billing:src/main/java/clinic/billing/InsuranceClient.java:41 `restTemplate.postForObject(url, claim, Claim.class)`
```

**Плохо:** `V-02 — исключение: страховая отвечает медленно`. Исключение придумано: никто его не решал.

**Хорошо:**

```
- [x] V-02 `billing`: внешний вызов без таймаута (лимит 3 с)
  - **Проверка:** таймаут задан бином RestTemplate: setReadTimeout(Duration.ofSeconds(20)) — billing:src/main/java/clinic/billing/HttpConfig.java:17
  - **Решение:** вопрос Q-004
```

Q-004: «Страховой шлюз отвечает до 20 с (HttpConfig.java:17) при стандарте 3 с: исключение для billing или асинхронная отправка?» —
кто ответит: архитектурный комитет. Проверка нашла и место настройки («без таймаута» оказалось неточным), и настоящий вопрос.

## Почему так

- Принцип — то, что проверяется и ломает что-то при нарушении; лозунг, пожелание и поведение одной системы — не принципы.
- У нарушения сначала «Проверка» по месту: эвристика ошибается, и это видно только в коде.
- Исключение заводит человек; без источника это нарушение или вопрос.
