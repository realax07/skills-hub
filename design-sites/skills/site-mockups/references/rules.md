## Куда класть результат

Пользователь указал путь — используй его. Иначе:

1. **Работаешь внутри репозитория сайта** — папка `mockups/` в корне репозитория (в монорепо — рядом с
   фронтенд-приложением, которое снимаешь: `apps/web/mockups/`). `plan.json` кладётся туда же.
   Если `mockups/` уже есть и создана не этим скиллом (нет `manifest.json` с `"generator": "site-mockups"`) —
   спроси пользователя, прежде чем писать в неё.
2. **Не в репозитории сайта** (сайт чужой, исходники лежат отдельно) — спроси пользователя, предложив `./<домен>-mockups/`.
3. Сообщи итоговый путь. Предложи добавить в `.gitignore` `mockups/**/*.png` и `mockups/.mockup-cache/`,
   если репозиторий не должен расти: HTML, CSS, README и manifest лёгкие, скриншоты и кэш — тяжёлые
   (кэш нужен только для частичной пересъёмки `--only`).

Почему так: единое предсказуемое место во всех репозиториях сайтов — агент всегда знает, где искать
дизайн-контекст, а дерево внутри повторяет разделы сайта.

## Указатель в контексте проекта

Мокапы бесполезны, если агент о них не знает. Файл инструкций проекта (AGENTS.md, CLAUDE.md…) агент читает
в каждой сессии, поэтому туда вписывается короткий блок: какие вопросы решают мокапы и путь до `GUIDE.md`.
Сам гайд и дерево агент открывает только под задачу про дизайн — основной контекст не раздувается.

1. Найди кандидатов: `node scripts/link-context.mjs --suggest --root <корень репо>`.
2. **Спроси пользователя**, куда вписать, — это правка его файла, который читают все агенты проекта. Предложи рекомендацию:
   - есть `AGENTS.md` — его (его читают Codex, OpenCode, Qwen Code, Hermes и др.; `CLAUDE.md` с `@AGENTS.md` подхватит его сам);
   - есть только `CLAUDE.md` / `GEMINI.md` / другой — его; несколько независимых файлов — можно все (`context` — массив);
   - нет ни одного — создать `AGENTS.md` в корне репо;
   - «никуда» — тоже ответ: тогда в отчёте дай путь до `GUIDE.md`, чтобы пользователь сослался сам.
3. Запиши выбор в план: `"context": "../AGENTS.md"` (путь от папки плана). Каждый прогон `capture` обновит блок;
   повторный прогон без изменений файл не трогает.

Блок стоит между `<!-- site-mockups:start -->` и `<!-- site-mockups:end -->`; текст вне меток не меняется.
Не переписывай блок руками — следующая съёмка его заменит; свои правила про мокапы пиши вне меток.
Убрать — `node scripts/link-context.mjs <out> --into <файл> --remove`.

## Дерево разделов

- Папки повторяют URL: `path` страницы в плане определяет её папку (`/blog/first-post` → `blog/first-post/`).
  Поэтому задавай реальные пути сайта, а не выдуманные: от них зависит, где агент будет искать контекст.
- Корень — главная. Общие компоненты (шапка, футер, общие модалки) снимай на главной: они окажутся в корне,
  на виду у всех разделов. Компонент, характерный для раздела (карточка статьи), снимай на странице раздела.
- Страница со `steps` — состояние: ложится в `_states/` папки своего `path`, а не в отдельную папку.
- Однотипных страниц (статьи, товары) — 1–2 представителя: раздел `blog/` с одной-двумя статьями даёт
  агенту образец, а не архив.
- Можно снимать страницы глубже без родителя (`/products/analytics` без `/products`) — промежуточная папка
  появится с README «страница раздела не снималась». Но если у раздела есть своя страница — сними её.

## Что снимать

Чек-лист охвата. Пройди по нему, когда пишешь план.

**Страницы (`pages`)** — каждый уникальный шаблон:
- главная, ключевые лендинги, каталог/список, карточка/деталь, статья, форма (контакты, оформление),
  личный кабинет / дашборд, настройки, 404 / ошибка, пустые состояния, логин/регистрация;
- однотипные (статьи, товары) — 1–2 представителя;
- значимые состояния целой страницы — отдельным pages-элементом со `steps` (`home--login-open`, `catalog--filters-open`):
  они показывают, как модалка лежит поверх компоновки.

**Компоненты (`components`)** — группы по умолчанию:

| Группа | Что |
|---|---|
| `layout` | header, nav, footer, sidebar, breadcrumbs |
| `sections` | hero, фичи, цены, отзывы, CTA, FAQ — крупные блоки страниц |
| `content` | карточки, списки, таблицы, бейджи, теги, аватары, медиа |
| `controls` | кнопки всех вариантов, ссылки-кнопки, переключатели |
| `forms` | поля, селекты, чекбоксы, формы целиком, состояния ошибок |
| `navigation` | табы, пагинация, степперы, меню |
| `feedback` | алерты, тосты, лоадеры, скелетоны, пустые состояния |

Варианты одного компонента (primary/secondary/ghost, размеры) — отдельными id
или одним элементом с `all: true`, если они различаются только контентом.

**Модалки и состояния (`modals`)** — всё, что появляется после действия:
модальные окна, дроверы, дропдауны, поповеры, тултипы, мобильное меню, раскрытые аккордеоны,
состояния ошибок валидации, cookie-баннер. Группа по умолчанию `modals`; дропдауны — `dropdowns`,
мобильное меню — `menus`, ошибки форм — `forms-states`.

**Вьюпорты:** desktop (1440×900) всегда; mobile (390×844, `isMobile: true`) — для страниц,
layout-компонентов и всего, что перестраивается. Мелкие контролы на мобиле обычно не нужны —
ограничь `viewports: ["desktop"]`.

## Медиа: дизайн или контент

Мокап хранит дизайн сайта, а не его контент. Фото статей, скриншоты продукта в карточках,
видео-истории клиентов — контент: следующий агент заменит их своими, а весят они десятки мегабайт.
Логотипы, иконки, фоны, шрифты, декоративные фоновые видео — дизайн, без них мокап не похож на сайт.

- По умолчанию контент заменяется заглушкой тех же пропорций: тег и классы остаются, вёрстка не едет,
  слот помечен `data-mockup-placeholder`, исходник — в `data-mockup-src`. Правила классификации — в
  [plan-format.md](plan-format.md#media).
- Посмотри каталог после съёмки: если логотипы клиентов или иллюстрации hero стали заглушками —
  добавь их контейнер в `media.design`; если фото статей скачались — в `media.content`.
- `verify` исключает заглушки из пиксельного сравнения и пишет, какую долю площади они заняли.
- Нужна полная копия со всем контентом — `"media": { "mode": "keep" }` и `capture.mjs --keep-video`.

## Именование и группы

- `id` — kebab-case, уникален в своём разделе: `pricing-card`, `button-primary`, `login`, `home--login-open`.
- Состояния — через `--`: `<основа>--<состояние>` (`signup--errors`, `header--menu-open`).
- `title` — по-человечески, на языке сайта: «Окно входа», «Карточка тарифа».
- `notes` — что это, где встречается, как открывается, особенности: «Открывается по „Войти“ в шапке; закрывается Esc».

## Селекторы

Приоритет: `#id` → `[data-testid]`/`[data-test]`/`[data-qa]` → роль/ARIA (`[role=dialog]`, `[aria-label="Меню"]`)
→ семантичные классы (`.site-header`, `.btn-primary`) → структурный путь (`main > section:nth-of-type(2)`).

Избегай: хэшей CSS-модулей и CSS-in-JS (`.sc-bdVaJa`, `.css-1x2y3z`, `._abc123`, `.Button_root__x8f2k`),
длинных цепочек от корня, текста, который меняется (цены, даты). Хэшированный класс можно частично
матчить: `[class*="Button_root"]`.

Проверь, что селектор находит ровно нужный элемент: если совпадений несколько — `index` или `all: true`.

## Модалки и состояния

- Открывай реальным действием (`click`, `hover`, `focus`, `press`), затем `waitFor` на появившийся элемент.
- Модалку с затемнением снимай двумя элементами: **сам диалог** в `modals/` (селектор окна, а не фона)
  и **страницу в этом состоянии** в `pages/` (`home--login-open`). Отдельный снимок полупрозрачного фона
  не совпадёт с оригиналом: на скриншоте сквозь фон видна страница, а в мокапе компонента её нет.
- Анимации раннер отключает сам, но если модалка монтируется с задержкой — добавь `{ "wait": 300 }`.
- Состояние ошибки формы: `click` по сабмиту пустой формы, `waitFor` на сообщение об ошибке.
- `hover`-состояния (тултипы) снимаются, а CSS `:hover` у самой кнопки — нет (см. ограничения).
- Если модалку не открыть без бэкенда (нужен ответ API) — снимай со стейджа, или замокай ответ через `eval`
  только если пользователь согласен; отметь в `notes`.

## Приватность и доступ

- Не снимай реальные персональные данные: используй тестовые аккаунты, в формы вписывай выдуманное.
- Пароли и токены не вводи сам и не клади в план. Для страниц за логином попроси пользователя
  сохранить сессию (например, `npx playwright codegen --save-storage=auth.json <url>`, логин делает он сам)
  и укажи `storageState` в плане. Файл сессии не коммить — добавь в `.gitignore`.
- Чужие сайты снимай только по просьбе пользователя и для его задачи; мокапы содержат чужой контент и ассеты.

## Ограничения и обходы

| Симптом | Причина | Что делать |
|---|---|---|
| В мокапе нет элемента, который видно на сайте | его рисует JS после загрузки / ленивая подгрузка | `steps: [{waitFor: "..."}]`; `defaults.settle` больше; `{scroll: "sel"}` |
| Картинки/шрифты не грузятся в мокапе | CORS или ассет за авторизацией | смотри `capture-log.json` → warnings; снимай со `storageState` |
| Мокап мобилки шире экрана | у сайта нет `<meta viewport>` — Chrome рисует 980px | это поведение оригинала, verify сравнит честно |
| `verify`: «картинка/CSS/шрифт не загрузился» | ассет не скачался при съёмке (CORS, авторизация, 404) | смотри warnings в `capture-log.json`; переснимай со `storageState` или с другого окружения |
| `verify` расхождение чуть выше порога на мелком элементе с текстом | субпиксельная растеризация (сглаживание и сдвиг до 1px уже отфильтрованы) | открой оба PNG; если визуально одинаково — объясни в отчёте, порог не поднимай для всех |
| В CSS `url("")` вместо фона | правило не сработало ни на одной снятой странице — файл не качали (так задумано: это не дизайн снятых страниц) | нужен этот фон — сними страницу или состояние, где он виден |
| Компонент «съехал» или сжался | стили зависят от соседей (`:nth-child`, `+`, flex-распределение) | сними группу целиком (родитель) или `fitSize: false` |
| Дропдаун/тултип стоит не там, где на сайте | оверлеи в мокапе компонента ставятся в поток (`data-mockup-position` хранит исходное) | так задумано; расположение смотри на pages-снимке со steps |
| Нет `:hover`/`:focus` у кнопок | статический HTML не держит псевдосостояния | правила `:hover` есть в CSS; при необходимости — скриншот после `hover` |
| `<video>` в мокапе не играет | файл видео не скачивается: у фонового видео в `poster` — кадр с экрана, у видео-контента — заглушка; исходник — в `data-mockup-src` | так задумано. Нужны сами файлы — `capture.mjs --keep-video` |
| Вместо картинки серый прямоугольник с крестом | это контент, заменённый заглушкой (см. «Медиа: дизайн или контент») | если это часть дизайна — добавь контейнер в `media.design` |
| Расхождение после сборки стилей в один файл (на странице появились чужие правила) | страница получает весь `styles.css` своего уровня, включая правила, которые подключали только соседние страницы; для CSS-модулей это безвредно, для глобальных стилей страниц — нет | `"cssBundle": false` в плане — стили останутся отдельными файлами |
| `canvas` пустой / график статичен | canvas сериализуется в картинку на момент снимка | норма; для интерактива — опиши в `notes` |
| `iframe` пустой | встроенные сторонние виджеты не сериализуются | исходный URL сохранён в `data-mockup-src` |
| Компонент в closed shadow DOM | закрытый shadow DOM недоступен | сними хост-элемент скриншотом; open shadow DOM поддержан |
| Шаг падает по таймауту | селектор не тот, элемент перекрыт, нужен скролл | проверь селектор в `discovery.json`; добавь `scroll`, закрой баннеры через `defaults.hide` |

## Типичные ошибки

- **Скачать HTML через curl/fetch** → на SPA получится пустой `<div id="root">`. Только через браузер.
- **Снять одну страницу и считать дело сделанным** → нет модалок и состояний, а именно они нужны агенту чаще всего.
- **Сто одинаковых карточек товаров** → раздувает контекст; 1–2 представителя на шаблон.
- **Хэш-классы в селекторах** → пересъёмка после следующей сборки сломается.
- **Пропустить verify** → незамеченные пустые блоки, потерянные шрифты, съехавшие компоненты.
