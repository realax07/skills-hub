# Site Mockups

Превращает работающий сайт в набор статических HTML-файлов, которые открываются без JS и сети
и выглядят как оригинал: страницы, компоненты, модалки и состояния, плюс токены, скриншоты и манифест.
Результат — контекст для AI-агентов, которые потом будут дорабатывать сайт или делать новые экраны в том же стиле.

Почему браузер, а не парсинг файлов: на современных сайтах разметку строит JS, модалки появляются
только после клика, а часть стилей (CSS-in-JS) существует только в рантайме. Скрипты скилла
рендерят сайт в Chromium и сериализуют то, что реально видит пользователь.

## Входные данные

- **URL сайта** — прод, стейдж или локальный dev-сервер. Если есть только папка со сборкой — раздадим её сами (`serve` в плане).
- **Исходники / статика + JS** — нужны, чтобы найти маршруты, модалки и то, как они открываются.
- **Куда класть** — если пользователь не сказал, выбери сам по правилам из [references/rules.md](references/rules.md#куда-класть-результат) и сообщи, куда положил.
- **Авторизация** — если нужные экраны за логином, попроси пользователя дать `storageState` (файл сессии Playwright) или тестовый аккаунт. Пароли сам не вводи и не храни.

## Процесс

Пути к скриптам — относительно папки этого скилла.

1. **Зависимости.** `node scripts/setup.mjs --check`. Если не ок — `node scripts/setup.mjs`
   (на Linux без системных библиотек — `--with-deps`, нужен sudo; спроси пользователя).
2. **Разведка.**
   `node scripts/discover.mjs --url <URL> --src <исходники> --out <out>/discovery.json`
   (или `--serve <папка сборки>` вместо `--url`). Получишь страницы, кандидатов в компоненты
   с селекторами, триггеры и подсказки из исходников (модалки, маршруты, компоненты).
   Затем **прочитай код** найденных модалок и триггеров — так ты поймёшь, какие состояния бывают
   и каким действием их открыть. Как искать — [references/finding-states.md](references/finding-states.md).
3. **План.** Запиши `<out>/plan.json`: страницы, компоненты по группам, модалки и состояния
   с шагами, вьюпорты (desktop + mobile). Формат — [references/plan-format.md](references/plan-format.md),
   чек-лист охвата — [references/rules.md](references/rules.md#что-снимать).
4. **Съёмка.** `node scripts/capture.mjs <out>/plan.json`. Упавшие элементы чини по сообщению
   (селектор, шаг, ожидание) и переснимай только их: `--only id1,id2`.
5. **Проверка.** `node scripts/verify.mjs <out>` — открывает каждый мокап без JS и сети, проверяет,
   что загрузились все картинки, CSS и шрифты, и сравнивает с оригинальным скриншотом (сглаживание
   и субпиксельный сдвиг уже учтены — остаток выше порога почти всегда реальная проблема).
   Для расхождений открой оба PNG и пойми причину
   (разбор типовых — в [references/rules.md](references/rules.md#ограничения-и-обходы)). Не отдавай результат, пока verify не зелёный
   или пока каждое оставшееся расхождение не объяснено.
6. **Отчёт пользователю.** Где лежит результат, сколько страниц, компонентов и модалок,
   что не удалось снять и почему, как переснять.

## Ключевые правила

- **Охват важнее красоты.** Каждый уникальный шаблон страницы, каждый тип компонента, каждая модалка и
  значимое состояние (открытое меню, ошибка формы, пустое состояние). Однотипные страницы (статьи, карточки товаров) — 1–2 представителя:
  агенту нужен образец, а не архив.
- **Устойчивые селекторы.** id, `data-testid`, роли, `aria-*`, семантичные классы. Не хэши
  CSS-модулей (`.sc-1x2y3z`, `.css-a8f2k`) — они меняются при каждой сборке, и пересъёмка сломается.
- **Модалки — через реальные действия** (`click`, `waitFor`), а не через подмену DOM в `eval`: так снимок
  совпадает с тем, что видит пользователь. `eval` — только когда действия не работают, и опиши это в `notes`.
- **Никаких реальных персональных данных.** Формы заполняй выдуманными значениями, личные кабинеты снимай под тестовым аккаунтом.
- **Понятные id и `title`, плюс `notes`** — для чего элемент и как он открывается. Манифест — это то, что будет читать
  следующий агент.

Полный свод — [references/rules.md](references/rules.md).

## Результат

```
<out>/
  index.html          каталог для человека: превью всего + токены
  README.md           описание для AI-агента: структура, как использовать
  manifest.json       машиночитаемый список: id, тип, группа, файл, скриншот, селектор, шаги, заметки
  plan.json           план съёмки — для пересъёмки
  pages/<id>.html                 страницы целиком (компоновка)
  components/<группа>/<id>.html   отдельные элементы: элемент + «скелет» его предков
  modals/<id>.html                модалки, дропдауны, состояния
  assets/css/*.css  assets/media/*    реально применённые стили (вкл. CSS-in-JS), картинки, шрифты
  screenshots/**.png              скриншоты оригинала той же структуры
  tokens.json  tokens.css         CSS-переменные и частотность цветов, шрифтов, размеров, радиусов, теней
  capture-log.json  verify-report.json
```

Мобильные версии — с суффиксом `--mobile` (имя второго вьюпорта).

## Примеры

**Запрос:** «Сделай мокапы нашего сайта для контекста агентов. Дев-сервер на localhost:5173, фронт в `apps/web/src`».
**Результат:** `discover` → чтение `apps/web/src` (роуты, `<Modal>`, `<Dialog>`) → `plan.json` на 8 страниц,
24 компонента, 6 модалок × desktop/mobile → `capture` → `verify` 100% → отчёт со ссылкой на `design/mockups/index.html`.

- [examples/01-marketing-site.md](examples/01-marketing-site.md) — сайт с dev-сервером и исходниками, полный проход
- [examples/02-spa-portal-modal.md](examples/02-spa-portal-modal.md) — SPA: модалка в портале, хэш-классы, дропдаун; как плохо и как хорошо

## Ресурсы

| Путь | Что там | Когда открывать |
|---|---|---|
| `references/rules.md` | что снимать, куда класть, именование, приватность, ограничения и обходы | перед планом и при расхождениях |
| `references/plan-format.md` | полный формат plan.json и шагов | при написании плана |
| `references/finding-states.md` | как найти модалки и состояния в коде разных фреймворков | на шаге разведки |
| `examples/` | разобранные прогоны | перед первым запуском |
| `assets/plan.example.json` | заготовка плана | копировать в `<out>/plan.json` |
| `scripts/setup.mjs` | установщик зависимостей (`--check` — проверка) | шаг 1 |
| `scripts/discover.mjs` | разведка: страницы, кандидаты, подсказки из исходников | шаг 2 |
| `scripts/capture.mjs` | съёмка по плану | шаг 4 |
| `scripts/verify.mjs` | сверка мокапов с оригиналом | шаг 5 |
| `scripts/lib/page-serialize.js` | сериализатор внутри страницы (чистый DOM) | если у агента свой браузер без Playwright: выполни `(<код>)({selector})` в странице |

У каждого скрипта есть `--help`.
