# Оформление заказа

## Purpose
Покупатель создаёт заказ из набора позиций и получает данные для оплаты картой. Оплата и её подтверждение — в order-payment.

## Requirements

### Requirement: Оформление только для вошедших
Система SHALL принимать заказ только от пользователя с действующим токеном входа.

#### Scenario: Нет токена
- **WHEN** запрос на создание заказа приходит без токена или с недействительным токеном
- **THEN** заказ не создаётся и возвращается ошибка 401

### Requirement: Проверка состава заказа
Система SHALL принимать заказ, в котором от 1 до 50 позиций (допущение: Q-001).

#### Scenario: Пустой заказ
- **WHEN** покупатель отправляет заказ без позиций
- **THEN** заказ не создаётся и возвращается ошибка 422

#### Scenario: Больше 50 позиций
- **WHEN** покупатель отправляет заказ из 51 позиции
- **THEN** заказ не создаётся и возвращается ошибка 422

### Requirement: Расчёт суммы заказа
Система SHALL считать сумму заказа как сумму «цена × количество» по ценам, переданным в запросе клиента. Возможная ошибка: по PRD цена берётся из каталога (допущение: Q-002).

#### Scenario: Сумма из позиций
- **GIVEN** заказ из 2 шт. по 100 ₽ и 1 шт. по 50 ₽
- **WHEN** покупатель оформляет заказ
- **THEN** сумма заказа — 250 ₽

### Requirement: Создание платежа
Система SHALL при создании заказа ставить ему статус NEW, создавать платёж в Stripe на сумму заказа в рублях и возвращать покупателю id заказа и секрет платежа для оплаты на клиенте.

#### Scenario: Заказ создан
- **WHEN** покупатель отправляет корректный заказ
- **THEN** заказ сохраняется со статусом NEW и привязкой к платежу
- **AND** возвращается 201 с id заказа и секретом платежа
