# Пример 1. Сервис заказов: полный проход (режим A)

Вход — тестовый проект из `evals/orders-service-with-prd/files/`: Express + Prisma, оплата Stripe с вебхуком, отгрузка через склад-партнёр
(BullMQ), автоотмена по cron, PRD в `docs/prd.md`.

**Запрос:** «Переводим orders-service на агентную разработку по OpenSpec. Сними спеку, как он работает сейчас. PRD — docs/prd.md. Вопросы — в файл, главные покажи».

## Ход

1. Входные данные: репозиторий и PRD названы; язык — русский; файлов инструкций нет → указатель в новый `AGENTS.md`.
2. `inventory.py scan .`:
   ```
   стек: .: Express
   входы: http 7, consumer 1, schedule 1
   вызовы наружу: 3, внешних хостов: 1, env: 11, сущностей: 3, тестов: 1, документов: 2
   ```
   Префиксы роутеров подставлены (`app.use("/api/orders", ordersRouter)` → `POST /api/orders/{id}/cancel`), вебхук помечен `webhook`,
   `/health` — `служебное`. SDK: stripe, nodemailer, bullmq, prisma; хост `api.warehouse-partner.ru`; TODO про цены из каталога, FIXME про частичный возврат.
3. Утверждения PRD для сверки: до 30 позиций; цена из каталога; автоотмена через 1 час; покупатель отменяет до отгрузки, оплаченный — с возвратом; чек на почту; отгрузку делает менеджер.
4. `plan.py init . --source docs/prd.md` дал черновые группы `orders`, `webhooks`, `queues`, `scheduler` — это код, не поведение. Переделано:
   ```
   plan.py rename . orders order-checkout --title "Оформление заказа"
   plan.py rename . webhooks order-payment --title "Оплата заказа"
   plan.py add-cap . order-viewing --title "Просмотр заказов"         # + move "http:GET /api/orders*"
   plan.py add-cap . order-cancellation --title "Отмена и возврат"    # + move cancel, merge scheduler
   plan.py add-cap . order-shipping --title "Отгрузка"                # + move ship, merge queues
   ```
   Автоотмена (cron) ушла в «Отмену», а очередь отгрузки — в «Отгрузку»: возможность объединяет входы по смыслу.
5. Цикл по возможностям. Для `order-checkout` `plan.py next` показал вход, файл, тест «rejects empty order with 422» и TODO.
   Чтение `orders.ts` → `MAX_ITEMS = 50`, сумма по `priceCents` из тела запроса → два расхождения с PRD → два вопроса:
   ```
   questions.py add . --title "Сколько позиций допускается в заказе: 30 или 50?" --category "расхождение кода и документа" \
     --importance блокирует --seen "PRD п.1 — от 1 до 30; код — MAX_ITEMS = 50 (src/routes/orders.ts:10)" \
     --affects "order-checkout / Проверка состава заказа" --assume "спека описывает код: до 50" --who "владелец продукта"
   ```
   Требование в спеке:
   ```markdown
   ### Requirement: Проверка состава заказа
   Система SHALL принимать заказ, в котором от 1 до 50 позиций (допущение: Q-001).

   #### Scenario: Больше 50 позиций
   - **WHEN** покупатель отправляет заказ из 51 позиции
   - **THEN** заказ не создаётся и возвращается ошибка 422
   ```
   Трассировка:
   ```
   ## order-checkout
   - Проверка состава заказа → src/routes/orders.ts:10-15 | тесты: test/orders.test.ts
   ```
   `check.py . --cap order-checkout` → без ✗ → `plan.py set . order-checkout --status done`. Так же остальные четыре.
6. Карта: в `integrations.md` — Stripe (обе стороны), склад (мы → они, при отказе 5 попыток, потом заказ висит в PAID), почта (ошибка письма роняет вебхук),
   сервис входа (токены); PostgreSQL и Redis — в «Инфраструктура». `domain.md` — переходы NEW → PAID → SHIPPED / REFUNDED, таблица прав.
7. `plan.py guide .`, `link.py . --file AGENTS.md`.
8. `check.py .` → `спек: 5, требований: 14, сценариев: 21 · вопросов: 8 · ✓ готово`.
9. `questions.py top . --n 7` — в чат.

## Результат (отчёт пользователю)

> Спека снята: 5 возможностей, 14 требований, 21 сценарий — `openspec/specs/`, карта — `system-context/GUIDE.md`, указатель — в `AGENTS.md`.
>
> **Код расходится с PRD в четырёх местах**, спека описывает код и помечена:
> 1. Q-001 — лимит позиций: PRD 30, код 50.
> 2. Q-002 — цену берут из запроса клиента, а не из каталога (рядом TODO) — похоже на ошибку.
> 3. Q-003 — автоотмена: PRD 1 час, код 30 минут.
> 4. Q-004 — покупатель в коде не может отменить оплаченный заказ, по PRD — может.
>
> Ещё 4 вопроса о внешнем мире (контракт склада, события Stripe, флаг частичных возвратов, кто вызывает API) — в `system-context/QUESTIONS.md`.
> Ответьте там в поле «Ответ» или здесь, затем скажите «внеси ответы». Изменения поведения дальше — через `openspec/changes/`.

## Почему так

- Вопросы о расхождениях — **блокирующие**: от них зависит, правильно ли агент поймёт деньги и права.
- Спека не «исправлена» под PRD: агент, опираясь на неё, должен видеть реальную систему.
- Ни одного вопроса «что делает эндпоинт» — это видно в коде.
