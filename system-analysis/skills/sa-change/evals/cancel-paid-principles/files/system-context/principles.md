# Принципы для систем этого репозитория (orders)

Копия из слоя архитектуры `../architecture`, пересобирается `rules.py link`. Перед задачей — прочти: это правила, которые нарушать нельзя без исключения (его заводит архитектор), а не пожелания.

### P-01. Сервис не читает чужую базу данных
- **Правило:** Сервис не читает и не пишет базу данных другого сервиса; чужие данные — через его API или события.
- **Почему:** Чужая база меняется без согласования: изменение схемы ломает соседа молча.
- **Как проверить:** скрипт: общие базы данных в ландшафте (`rules.py verify`)
- **Нарушается здесь сейчас:** база `orders db (DATABASE_URL)` общая с warehouse-sync — не повторяй и не расширяй

### P-02. Таймаут внешних вызовов не больше 5 секунд
- **Правило:** Каждый внешний HTTP-вызов задаёт таймаут не больше 5 секунд.
- **Почему:** Без таймаута зависший сосед держит запросы вызывающего — отказ расползается по цепочке.
- **Как проверить:** скрипт: у внешних HTTP-вызовов таймаут не больше 5 с (`rules.py verify`)
- **Нарушается здесь сейчас:** внешний вызов без таймаута (лимит 5 с) — src/integrations/stripe.ts:3 `new Stripe(process.env.STRIPE_SECRET_KEY!, { apiVersion: … })` — не повторяй и не расширяй

### P-03. Денежные операции — с ключом идемпотентности
- **Правило:** Списание и возврат выполняются с ключом идемпотентности: повтор запроса не создаёт второй операции.
- **Почему:** Ретрай клиента или повторная доставка события иначе списывают или возвращают деньги дважды.
- **Как проверить:** скрипт: в коде должно быть `(?i)idempot|Idempotency-Key` (`rules.py verify`); на ревью: «Что вернёт повторный запрос с тем же заказом — та же операция или вторая?»
- **Нарушается здесь сейчас:** не найдено обязательное `(?i)idempot|Idempotency-Key` — не повторяй и не расширяй

### P-04. Обработчик события идемпотентен
- **Правило:** Повторная доставка события или задачи очереди не меняет результат обработки.
- **Почему:** Брокер и очередь доставляют хотя бы один раз: дубль неизбежен.
- **Как проверить:** на ревью; на ревью: «Что будет, если это событие придёт дважды?»

### P-05. Секреты не в коде
- **Правило:** Секреты не хранятся в коде и репозитории — только в переменных окружения или хранилище секретов.
- **Почему:** Утёкший ключ платёжки — деньги.
- **Как проверить:** скрипт: в коде не должно быть `(sk_live_[A-Za-z0-9]{8,})` (`rules.py verify`)
