# Пример 1: отмена оплаченного заказа покупателем — полный проход

Прогон агента на Haiku по фикстуре сервиса заказов (Express + Prisma + Stripe + очередь отгрузки), слой sa-scan собран.
Пакет прошёл `change.py check` и `openspec validate` с первого полного круга, код проекта не тронут.

## Запрос

> Хотим, чтобы покупатель мог сам отменить и оплаченный заказ, пока его не отгрузили; деньги возвращаем через Stripe.
> Спланируй изменение для разработчиков-агентов. Меня не будет до вечера — спросить некого.

## Ход

1. `change.py layer` — слой свежий по git, блокирующих вопросов 2, design-context и test-cases нет.
2. `change.py find --text "покупатель отменяет оплаченный заказ с возвратом денег"` → `order-cancellation` (34), дальше с отрывом —
   оплата, просмотр, отгрузка. По карточкам: меняются **order-cancellation** (кто и когда может отменить) и **order-shipping**
   (отгрузка не должна начаться, пока идёт отмена).
3. `change.py new … cancel-paid-by-customer --title "Отмена оплаченного заказа покупателем"`,
   `change.py analyze … --cap order-cancellation,order-shipping --entity Order` → очередь `ship`, место создания заказа, миграция,
   Q-003 и Q-004 [блокирует].
4. Чтение кода по трассировке выявило то, чего нет в слое, — агент дописал пункты `X`: гонку отмены и отгрузки (воркер проверяет PAID
   и только потом зовёт склад), `attempts: 5` в опциях Worker (BullMQ берёт их из опций задания — повторов может не быть),
   тест-заглушку `expect(true)` «customer cannot cancel paid order», отсутствие клиента API в репозитории.
5. Дельты: MODIFIED «Отмена заказа покупателем» через `change.py req` — оба исходных сценария сохранены, «Оплаченный заказ» переписан
   (было 409, стало 200 и возврат), добавлен «Отгрузка уже начата»; MODIFIED «Отмена оплаченного заказа с возвратом» — идемпотентность
   возврата и 502 при ошибке Stripe; две MODIFIED в order-shipping.
6. design.md: два nullable-поля `cancelStartedAt`, `shipStartedAt` и условные `updateMany` вместо нового статуса — захват заказа
   либо отменой, либо отгрузкой; ключ идемпотентности возврата `cancel-<orderId>`.
7. tasks.md — 11 задач, решения у всех 11 пунктов влияния, `check`: 0 ошибок.

## Почему так

- Влияние из слоя дало стартовый список, а чтение кода по трассировке — то, чего слой не видит (гонка, BullMQ): пункты `X` для этого.
- Гонку решили в design, а не оставили dev-агенту: «как не допустить двойного возврата» — решение аналитика.
- Блокирующие вопросы не решены молча: принятые допущения названы, последствия другого ответа — тоже.
- Задачи с файлами, требованиями и критерием; порядок и «не параллельно» там, где задачи делят файл.
