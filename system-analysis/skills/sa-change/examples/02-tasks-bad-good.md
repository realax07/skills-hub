# Пример 2: задачи и влияние — плохо и хорошо

Задача: «у товара каталога появляется вес в граммах; задают при создании и правке, показываем на витрине и сохраняем в позиции заказа».
Проект — микросервисы .NET (каталог, корзина, заказы, витрина, мобильный клиент), слой sa-scan собран.

## Влияние

**Плохо** — `analyze` запущен только с `--cap catalog-management`, без `--entity CatalogItem`:

```
## Кто вызывает затронутые входы
- [x] C-01 `src/ClientApp → /api/catalog` — клиентское приложение
  - **Решение:** не затрагивается: не нужно
```

Мест создания, копий, засева в плане нет вовсе, а решение у клиента — без причины. Dev-агент добавит поле в модель и API,
а вес тихо потеряется в ручном копировании при создании товара, в засеве, в маппинге позиции заказа.

**Хорошо** — `analyze --cap catalog-management,order-placement,storefront --entity CatalogItem --entity OrderItem`:

```
## Кто вызывает затронутые входы
- [x] C-01 `src/ClientApp → /api/catalog` — клиентское приложение
  - опирается на: читает id, name, price, pictureUri; свой класс CatalogItem (src/ClientApp/Models/Catalog/CatalogItem.cs)
  - **Решение:** не затрагивается: в задаче мобильный клиент не упомянут, лишнее поле JSON он игнорирует (System.Text.Json) — в «Открытые вопросы»: нужен ли вес в приложении
- [x] C-02 `src/eShop.AppHost → /api/catalog`
  - **Решение:** не затрагивается: шлюз пробрасывает путь целиком, поля не трогает

## Сущности: где поле потеряется молча
- [x] E-01 `CatalogItem` создаётся: `CatalogApi.CreateItem` src/Catalog.API/Apis/CatalogApi.cs:419
  - **Решение:** задача 1.3
- [x] E-02 `CatalogItem` создаётся: `CatalogContextSeed.SeedAsync` src/Catalog.API/Infrastructure/CatalogContextSeed.cs:48
  - **Решение:** задача 1.4
- [x] E-05 `CatalogItem` → копия `CatalogItem` (src/WebAppComponents/Catalog/CatalogItem.cs:3)
  - **Решение:** задача 3.1
- [x] E-07 `CatalogItem` засев: src/Catalog.API/Infrastructure/CatalogContextSeed.cs (только в пустую таблицу)
  - **Решение:** задача 1.5
- [x] E-08 `CatalogItem` уходит в модель ИИ: src/Catalog.API/Services/CatalogAI.cs:75
  - **Решение:** не затрагивается: в эмбеддинг идут только Name и Description (строка 75), вес туда не попадёт
```

## Задачи

**Плохо:**

```
## 1. Реализация
- [ ] 1.1 Добавить вес товару
- [ ] 1.2 Показать вес на витрине
- [ ] 1.3 Сохранять вес в заказе
- [ ] 1.4 Написать тесты
```

Ни мест, ни критериев: dev-агент угадывает, что «вес» — это `int` или `decimal?`, где витрина берёт данные, сколько мест копирования.
`check`: требования дельт не названы в задачах, у задач нет файлов, нет обновления trace.md.

**Хорошо:**

```
## 1. Данные и контракты
- [ ] 1.1 Добавить `WeightGrams int?` в `CatalogItem` — src/Catalog.API/Model/CatalogItem.cs — готово, когда: свойство есть, сборка проходит
- [ ] 1.2 Миграция `AddCatalogItemWeight` — src/Catalog.API/Infrastructure/Migrations/ — готово, когда: снимок совпадает с моделью, колонка nullable
- [ ] 1.3 Копировать WeightGrams при создании — `CatalogApi.CreateItem` (src/Catalog.API/Apis/CatalogApi.cs:419) — готово, когда: требование «Создание товара», сценарий «Товар с весом»
- [ ] 1.4 Засев: WeightGrams из catalog.json — `CatalogContextSeed.SeedAsync` и `CatalogSourceEntry` — готово, когда: новый засев заполняет вес
- [ ] 1.5 Миграция данных: вес существующих товаров NULL — показывать «—» (design, «Данные и контракты») — готово, когда: старые товары открываются без ошибки
## 2. Поведение
- [ ] 2.1 PUT товара без поля weightGrams не обнуляет вес — `CatalogApi.UpdateItem` — готово, когда: требование «Правка товара», сценарий «Правка без веса»
## 3. Вызывающие и подписчики
- [ ] 3.1 Поле WeightGrams в `CatalogItem` витрины — src/WebAppComponents/Catalog/CatalogItem.cs — готово, когда: карточка показывает вес
…
## 5. Слой контекста
- [ ] 5.1 Обновить system-context/trace.md …
```

## Почему так

- `--entity` превратил «добавить поле» в список мест, где оно теряется молча: создание, засев, копии, ИИ.
- У каждого «не затрагивается» — проверяемая причина; спорное (мобильный клиент) — ещё и вопрос.
- Задача — одно место, что сделать и «готово, когда»; имена требований дельт названы — `check` это сверяет.
- Решение о `PUT` без веса (обнулять или нет) принято в design, а не оставлено dev-агенту.
