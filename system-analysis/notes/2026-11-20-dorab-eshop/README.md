## С кодом: слой или без (2026-11-24)

Агент на Haiku получает весь репозиторий и ту же задачу. В одной копии есть слой sa-scan и указатель в AGENTS.md, в другой — только код.
Файлы `withcode-*`, оценка вслепую — `withcode-scores.md` (тот же чек-лист).

| | без слоя | со слоем |
|---|---|---|
| A — отмена после оплаты | 9,0 | 11,0 |
| B — вес товара | 10,5 | 10,5 |
| токены, время (A / B) | 167k, 3,2 мин / 171k, 3,5 мин | 182k, 3,4 мин / 165k, 3,5 мин |

Слой помог там, где риск не виден из одного места кода: сгоревший `x-requestid`, общая команда отмены, поведение шины и outbox
(это пришло из пометок и вопросов). Для поля сущности код читается и без слоя: цепочку маппинга, засев, PUT Haiku нашёл сам.
Цена — та же. По одному прогону на вариант: разница в 2 балла может быть шумом.

## Под слабые модели (2026-11-24)

Целевые модели — GLM Flash, DeepSeek, Qwen: большие файлы целиком не читают, плотные строки разбирают плохо, указатель-прозу не выполняют.
Поэтому: карточки `caps/<id>.md` (~3 тыс. токенов, пример — `card-example-order-management.md`), один факт на строку и `Класс.Метод`
рядом с номером строки, ссылки `путь:строка` обязательны в заполненных местах, указатель в AGENTS.md — пошаговый чек-лист с grep.
Прогонов на целевых моделях ещё не было.

## sa-change на eShop (2026-11-26)

Агент на Haiku по скиллу sa-change, автономно, слой sa-scan текущей версии. Пакеты прошли `change.py check` и `openspec validate`,
код не тронут. Оценка вслепую по тому же чек-листу (`sa-change-scores.md`, пакеты — `sa-change-*-plan.md`):

| | A — отмена после оплаты | B — вес товара |
|---|---|---|
| sa-change, Haiku | 8,5 | 10 |
| раньше: план по слою без кода, Sonnet | 11,5 | 10,5 |
| раньше: Haiku с кодом и слоем | 11,0 | 10,5 |

Исполнимость задач для слабой модели (оценщик): A — 3/5, B — 4/5. Полноту влияния sa-change пока не поднял: факт «событие оплаты несёт
только OrderId» в пакете был, а вывода «возврату не хватает ссылки на платёж» модель не сделала; гонка с 10-секундной паузой названа частично.
Шум: в B восемь блокирующих вопросов, не относящихся к весу, — их требовал `check` (исправлено: вопрос, на который изменение не опирается, —
«не затрагивается»). Добавлен прямой вопрос «хватит ли полей события новому поведению».
