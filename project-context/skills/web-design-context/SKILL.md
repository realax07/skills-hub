# Web Design Context

Первый шаг подготовки существующего проекта к агентной разработке — дизайн. Скилл даёт агентам материал для сборки:
**основы**, **детали с вариантами**, **схемы разделов**, **ассеты** и, если есть код, **где это задано в исходниках**.
Агент, который потом делает фичу, грузит один нужный файл (единицы тысяч токенов) и делает новое как существующее.

Два источника, оба с целевого проекта:
- **Сайт в браузере** — основа, работает всегда: вычисленные стили, итоговая разметка, открытые модалки. Системы бывают
  любые (вёрстка без компонентов, CSS-in-JS, JS-анимации) — то, что видит пользователь, есть всегда.
- **Исходники** (если доступны) — `"src"` в плане: где определены переменные и темы, какие варианты заданы в коде,
  какие компоненты переиспользовать, какой файл рисует деталь. Без исходников всё остальное работает так же.

## Как выполнять

Для любой модели: запускай команды как написано, пути к скриптам — от папки скилла (`<skill>` ниже).
Не придумывай флаги — у каждого скрипта есть `--help`. Скрипт упал — смотри «Если что-то не так» ниже, не обходи вручную.
Шаги 1–7 — по порядку; вопросы пользователю — одним сообщением на шаге 2.

## Процесс

1. **Зависимости.**
   `node <skill>/scripts/setup.mjs --check` → все строки с ✓ — дальше; есть ✗ — `node <skill>/scripts/setup.mjs`.

2. **Входные данные — спроси одним сообщением то, чего нет в запросе:**
   - **Сайт:** URL (прод, стейдж, `http://localhost:5173`) или папка сборки (`dist/`).
   - **Исходники:** папка фронтенда (`src/`, `apps/web`). Есть в репо — используй, не спрашивая.
   - **Позиция проекта** (`stance`): новое **повторять как есть** (`preserve`: легаси, строгий регламент) или **приводить к канону**
     (`normalize`). Сказано в запросе («стиль не меняем», «легаси не тащим») — не переспрашивай.
   - **Указатель:** в какой файл инструкций вписать ссылку на гайд. Варианты: `node <skill>/scripts/link-context.mjs --suggest --root .`.
   - **За логином?** Тогда `storageState` от пользователя (rules.md, «Приватность»). Пароли сам не вводи.
   - Куда класть — по умолчанию `design-context/` в корне репозитория ([правила](references/rules.md#куда-класть-результат)).
   - **Спросить некого** (автономный прогон, пользователь не отвечает) — не решай за владельца:
     `stance` не задавай (в `GUIDE.md` будет «не задана»), `context` не задавай (файлы инструкций не трогай),
     в отчёте — оба вопроса и путь до `GUIDE.md`. Что пользователь сказал сам («стиль не меняем», «пропиши в AGENTS.md») — выполняй.

3. **Разведка.**
   `node <skill>/scripts/discover.mjs --url <URL> --src <исходники> --out design-context/discovery.json`
   (папка сборки вместо URL — `--serve dist`). Даёт страницы по разделам, кандидатов в компоненты, триггеры модалок,
   маршруты и модалки из кода, сводку дизайна в коде. Как найти состояния в коде — [references/finding-states.md](references/finding-states.md).

4. **План** `design-context/plan.json` — скопируй [assets/plan.example.json](assets/plan.example.json), формат — [references/plan-format.md](references/plan-format.md).
   Обязательно: `baseUrl` или `serve`; `pages` — по представителю на каждый шаблон страницы; `stance`.
   Если есть: `src` (путь от папки плана, `"../src"`), `context` (`"../AGENTS.md"`), `modals` со `steps`, `components`.
   В `modals.selector` — само окно (`[role=dialog]`, `.modal`), **не подложку** на весь экран: подложку видно в состоянии страницы.
   Кнопки, поля, ссылки, бейджи в план не перечисляй — их найдёт извлечение. Чек-лист охвата — rules.md, «Что снимать».

5. **Съёмка.** `node <skill>/scripts/capture.mjs design-context/plan.json`.
   В конце — сводка: файлы, число вариантов деталей, разброс, ошибки. Код выхода 1 — что-то не снялось:
   исправь план, затем `--only <id1>,<id2>`.

6. **Разбор деталей** — что из найденного канон, вариант, шум ([правила](references/rules.md#разбор-деталей)).
   - `node <skill>/scripts/parts.mjs design-context` — сводка по группам.
   - `node <skill>/scripts/parts.mjs design-context --group buttons` — варианты текстом: частота, страницы, стиль, классы, исходник.
     С картинками удобнее: `reference/parts.html` (вырезки) — если умеешь смотреть изображения.
   - Пометить: `parts.mjs design-context --set <id>=canon:"Кнопка основная" <id>=variant:"На тёмном" <id>=noise`;
     остальное в группе разом: `--group buttons --rest noise`. Слой пересобирается сам.
   - Канон — частый, на многих страницах, понятная роль. Шум — редкий, почти копия другого, не та категория
     (пункт меню среди кнопок). Сомневаешься или «канонов» больше ~6 в группе — покажи пользователю список и спроси.

7. **Проверка и отчёт.**
   - `node <skill>/scripts/verify.mjs design-context` — эталон сверяется с оригиналом.
   - Открой `GUIDE.md`, `foundations.md`, один `parts/*.md` как агент-потребитель: хватит, чтобы сделать новую кнопку или секцию «как здесь»?
   - Отчёт пользователю: где лежит, позиция, ключевые цвета, шрифты, движение, канон по группам, разброс, что найдено в коде,
     куда вписан указатель, что не снято и почему, предложение добавить `design-context/reference/` в `.gitignore`.

## Ключевые правила

- **Не размножай шум.** Найденное — описание того, что есть, а не норма. Норму задают разбор (шаг 6) и позиция проекта.
- **Композиции так же важны, как детали.** Правильные кубики без схем разделов дают усреднённый, пустой дизайн —
  снимай каждый шаблон страницы и ключевые состояния.
- **Состояния — реальными действиями** (`click`, `waitFor`), не подменой DOM: иначе детали и схемы врут.
- **Код — источник «где», браузер — источник «что».** Значение в `foundations.md` и переменная в `source.md` расходятся —
  верь браузеру (так видит пользователь) и отметь расхождение в отчёте.
- **Устойчивые селекторы**, без хэшей CSS-модулей и сгенерированных id — план должен переигрываться.
- **Никаких персональных данных** в формах и кабинетах; пароли не вводи — только `storageState`.
- Подробно: [references/rules.md](references/rules.md).

## Результат

```
design-context/
  GUIDE.md                 вход для агента: вопросы, задача → файл, позиция проекта, указатель
  foundations.md           цвета (роль, значение, CSS-переменная, частота), типографика, отступы, радиусы, тени, движение, разброс
  parts/
    buttons.md inputs.md links.md badges.md cards.md   варианты: статус, стиль, разметка, где встречается, исходник
    components.md          компоненты из плана (шапка, футер, формы, секции) — сжатая разметка
    overlays.md            модалки, меню, поповеры из плана — как открыть + разметка
  compositions/<раздел>.md сжатая схема страницы раздела и его состояния; общие компоненты — ссылками
  source.md                (если есть "src") стек, токены и темы в коде, варианты cva/styled, компоненты, анимации, иконки, шрифты
  assets/                  fonts/  icons/*.svg  logos/  tokens.css
  plan.json  discovery.json
  reference/               эталон и служебное, агенту-потребителю читать не нужно:
                           дерево страниц-снимков (HTML + скриншоты), parts.html (вырезки), kit.json (всё извлечённое),
                           parts-source.json (деталь → файл), manifest.json, tokens.json, capture-log.json, verify-report.json, .cache/
```

Размер: основы — 1–3 тыс. токенов, файл деталей — 1–5 тыс., `source.md` — 1–8 тыс., схема раздела — 1–30 тыс.
`reference/` — десятки мегабайт скриншотов: не коммитить. Слой для агента лёгкий — коммитить.
Указатель `capture` вписывает в файл из `context` между метками `<!-- web-design-context:start/end -->`, остальной текст не трогает.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| `setup --check` не готов, `setup` падает на Linux | `node <skill>/scripts/setup.mjs --with-deps` (нужен sudo) или попроси пользователя |
| `capture`: шаг падает по таймауту | селектор не тот или перекрыт баннером: проверь в `discovery.json`, добавь `defaults.hide`, шаг `scroll` |
| `verify` не проходит у модалки (5–10%) | в `selector` попала полупрозрачная подложка — укажи само окно (`[role=dialog]`), `--only <id>` |
| в сводке «нет <meta name=\"viewport\">» | не ошибка: сайт на телефоне рисуется как десктоп; это уже записано в `foundations.md` — упомяни в отчёте |
| `capture`: страница пустая или «войдите» | нужна сессия: `storageState` (rules.md, «Приватность»); сам не логинься |
| в группе деталей сотни вариантов | норма для легаси: разбор, `--rest noise` после пометки канона |
| `source.md` нет | в плане нет `"src"` или путь неверный (считается от папки плана) — смотри предупреждение в сводке |
| в `source.md` «CSS-переменных нет, а на сайте их N» | стили лежат вне `src`: добавь их папку в `src` (массив); для статики без сборки — папку со стилями сайта |
| у деталей нет строки «исходник» | классы собираются динамически или сгенерированы — норма; ищи по тексту и стилю |
| `verify` ниже порога | `reference/capture-log.json` → warnings (ассет не скачался); подробности — rules.md, «Ограничения» |
| `--rebuild`: «нет manifest.json» | съёмки ещё не было — сначала `capture.mjs plan.json` |

## Пример

**Запрос:** «Подготовь дизайн-контекст нашего сайта для агентов, дев-сервер на :5173, код в apps/web/src».
**Ход:** setup → вопросы (позиция, AGENTS.md) → discover → план на 7 страниц, 2 модалки, 5 компонентов, `src`, `stance: normalize` →
capture → `parts.mjs --group buttons`: из 14 вариантов канон 3 → verify → отчёт.

- [examples/01-marketing-site.md](examples/01-marketing-site.md) — полный проход по сайту с исходниками
- [examples/02-spa-portal-modal.md](examples/02-spa-portal-modal.md) — SPA с порталами и хэш-классами; плохо и хорошо
- [examples/03-legacy-noise.md](examples/03-legacy-noise.md) — легаси с разбросом: разбор вариантов и позиция «повторять как есть»

|---|---|---|
| `references/rules.md` | куда класть, позиция, указатель, что снимать, разбор, исходники, селекторы, медиа, приватность, ограничения | перед планом и при разборе |
| `references/plan-format.md` | все поля plan.json: страницы, шаги, `src`, `parts`, `stance`, `context`, медиа | при написании плана |
| `references/finding-states.md` | как найти модалки и состояния в коде разных фреймворков | на разведке |
| `examples/` | разобранные прогоны | перед первым запуском |
| `assets/plan.example.json` | заготовка плана | копировать в `design-context/plan.json` |
| `scripts/setup.mjs` | ставит Playwright и Chromium (`--check`, `--with-deps`) | шаг 1 |
| `scripts/discover.mjs` | разведка: обход сайта, маршруты и модалки в коде, сводка дизайна в коде | шаг 3 |
| `scripts/capture.mjs` | съёмка, извлечение, сканирование исходников, сборка слоя (`--only`, `--rebuild`, `--clean`, `--no-screenshots`) | шаг 5 |
| `scripts/parts.mjs` | разбор деталей текстом: список, `--set`, `--rest` (пересобирает слой) | шаг 6 |
| `scripts/verify.mjs` | сверка эталона с оригиналом (`--only`, `--threshold`) | шаг 7 |
| `scripts/link-context.mjs` | `--suggest` — файлы инструкций в репо; вписать/убрать указатель без пересъёмки | шаг 2 |
| `scripts/lib/source-scan.mjs` | сканер исходников: стек, токены, темы, варианты, компоненты; привязка деталей к файлам | читать не нужно |
| `scripts/lib/context.mjs` | сборка слоя для агента (GUIDE, foundations, parts, compositions, source, assets) | если нужно поменять формат слоя |
| `scripts/lib/build.mjs` | сборка эталона `reference/` из кэша съёмки | читать не нужно |
| `scripts/lib/guide.mjs` | текст и вставка блока-указателя в AGENTS.md и др. | читать не нужно |
| `scripts/lib/page-extract.js` | в странице: основы, детали, иконки, логотипы, движение | если у агента свой браузер без Playwright |
| `scripts/lib/page-outline.js` | в странице: сжатая схема разметки | то же |
| `scripts/lib/page-serialize.js`, `page-tokens.js`, `page-discover.js` | в странице: снимок HTML, CSS-переменные и частоты, кандидаты для разведки | то же |
| `scripts/lib/runtime.mjs`, `serve.mjs`, `steps.mjs` | загрузка Playwright, локальный сервер для `serve`, выполнение шагов | читать не нужно |
| `evals/` | тест-кейсы скилла | при доработке скилла |

Переменные окружения: `WEB_DESIGN_CONTEXT_HOME` — куда ставить зависимости, `WEB_DESIGN_CONTEXT_PLAYWRIGHT` — версия Playwright.
